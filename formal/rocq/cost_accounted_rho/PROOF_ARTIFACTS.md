# Cost-Accounted Rho Proof Build Artifacts

Rocq proof certificates are build products for the cost-accounted rho formal model and are intentionally not tracked. The verification script regenerates them from source before checking headline theorem closure.

- Native candidate ordering refinement: `CostAccountedRho.NativeCandidateDigestCache` proves that caching each candidate digest preserves the digest-and-original-index comparison and the resulting candidate order in the comparison-sort model. The proof assumes a pure digest function and does not verify the Rust serializer or Blake2 implementation.
- Canonical candidate order from source hashes (I1, DR-75): `CostAccountedRho.CandidateSourceOrder` proves that the two-phase order (sort by source hash and index, then re-sort each tie run by digest and index) equals the canonical (source, digest, index) order, that phase one reads no digest, that a digest is computed only for a candidate whose source hash occurs at least twice, that the payload order does not depend on insertion order, and that filtering commutes with the sort. Proved counterexamples show that an index-only key and a source-only key both depend on insertion order. The payload (source, digest) stands for the candidate value, so the value-level claim relies on digest collision resistance, which the model does not verify.
- Read-coverage of the metered COMM observation (C12, DR-76): `CostAccountedRho.ObservationReadCoverage` models a metered run as reservation and read events and proves that the C12 COMM observation reserves before every unmetered read (prefix coverage), performs the same reads as the legacy construction, and charges exactly one COMM inspection and one continuation inspection less. The C12 charge does not depend on the continuation body or guard. A proved counterexample shows that the legacy charge grew with the unread body. The model abstracts sizes as natural numbers and does not verify the Rust traversal code.
- Incremental tree backing (C13, DR-77): `CostAccountedRho.IncrementalTreeBacking` proves that the increment charges of any sequence of B-tree batches telescope to the backing of the final tree, for bytes and for operations. After every prefix of single inserts, the cumulative reservation covers every node of a B-tree with that many entries (via `NativeCheckpointBacking.checkpoint_node_count`). It also proves that the legacy whole-tree charge per insert grows quadratically while the incremental charge stays linear. The model abstracts the node layout as a constant and does not verify the Rust `BTreeMap` implementation. The Rust property test checks the coverage against the real allocator.
- Ordered lookup bound (C3, DR-78): `CostAccountedRho.OrderedLookupBound` models a B-tree with the node bounds of the standard `BTreeMap`: at most 11 keys in a node, at least 5 keys in every node except the root, and leaves at one depth. It proves that a well-formed subtree of height h holds at least 6^h - 1 entries and that a root of height h + 1 holds at least 2 * 6^h - 1 entries (`btree_size_lower_bound`). It also proves that a left-to-right scan search makes at most 11 * h key comparisons (`btree_search_comparisons`) and that the height is at most `height_bound` of the size (`btree_height_bound`). `height_bound` is the function that the Rust charge computes, so one search makes at most 11 * `height_bound` (size) comparisons (`search_within_size_bound`). The model does not verify the Rust `BTreeMap` implementation. The Rust property tests count the comparisons of the real `BTreeMap` with a counting key type for maps of up to 2^16 entries, built by single inserts in random, ascending, and descending order, by the bulk build, and by inserts followed by removals.
- Replay authority tree bound (C14, DR-79): `CostAccountedRho.OrderedLookupBound` also proves that `height_bound` is monotone (`height_bound_monotone`), that a search reads at most h nodes (`search_visits_le_height`), and that a search in a map with at most n entries makes at most 11 * `height_bound` n comparisons and reads at most `height_bound` n nodes (`search_within_bound`). So a charge is sound when its size bounds the map at the time of the search. Two proved negative controls show the two unsound sizings: a deferred search charged at the size before the operation (`pre_operation_size_undercharges`), and one bound for the summed size of two maps (`summed_size_undercharges`, two 77-entry trees whose searches make 44 comparisons against a bound of 33). The Rust property test counts the comparisons and measures the allocations of the real map operations of a replay publication.
- Shared native continuation reads (C1, DR-81): `CostAccountedRho.NativeSharedReads` proves that selection over shared views equals selection over copied payloads (`shared_selection_equals_deep_selection`), that a prefetch followed by a read equals the read (`prefetch_then_read_equals_read`), that every step keeps each live payload's release prepaid (`cleanup_prepaid_preserved`), and that no payload is released unpaid (`every_release_was_prepaid`). A proved negative control shows that a cold fill without prepayment leads to an unpaid release. `NativeSharedReadCleanup.tla` checks the same invariants with two unsafe controls. The model does not verify the Rust `Arc` implementation.
- Copy-free native data views (C2, DR-82): `CostAccountedRho.NativeSharedReads` also proves that a cold read that reserves before it inserts leaves the cache unchanged when a reservation is rejected (`rejected_cold_read_leaves_cache`) and otherwise equals the read (`accepted_cold_read_equals_read`). A proved negative control shows that a read that inserts before it reserves leaves the cache filled after a rejection (`insert_first_fills_cache_on_rejection`). Shared-view selection (`shared_selection_equals_deep_selection`) covers the borrowed datums of a shard snapshot.
- Shared pointer cleanup (C5, DR-83): `CostAccountedRho.NativeSharedReads` also proves that a replace of a cache entry, which copies and drops pointers only, releases no payload unpaid from a state where every live payload is prepaid (`shared_replace_needs_no_payload_cleanup`). The Rust charge therefore visits each store-owned pointer and skips its payload.
- Detached path compaction (C9, DR-84): `CostAccountedRho.DetachedPathCompaction` describes each generated causal path by its units (an operation, or a child of a split) and proves that the compacted rendering, which gives child i of a split at step s the one segment (s, i + 1), compares like the legacy rendering (s, 1)·(i, 0) for all unit lists (`render_order_isomorphism`, `fuse_order_isomorphism`). The map from legacy to compacted paths is therefore injective (`fuse_injective`). A participant path below k splits has k segments instead of 2k, and an operation path has k + 1 instead of 2k + 1 (`fuse_halves_participant_depth`, `funding_flow_depth`: 513 instead of 1,025 for k = 512). A proved negative control shows that the fusion into (s, i) gives an operation and a first child the same path (`naive_fusion_collides`). The model does not verify the Rust `CausalPath` skip-list comparison, which the Rust tests check against the vector order.
- Chained causal-path digests (C7a, DR-85): `CostAccountedRho.NativePathTrie` (part 1) models the path digest as an abstract root digest and child digest whose collision freedom is a theorem premise, and proves that two paths have equal chained digests exactly when they are equal (`digest_chain_correct`, from `chain_snoc`). Two recording occurrence keys (session, digest, depth, last segment, stage) are therefore equal exactly when their sessions, paths and stages are equal (`occurrence_key_correct`). A proved negative control shows that a key that hashes only the last segment gives two different paths the same key (`unchained_digest_collides`). The model does not verify Blake2b-256, whose collision resistance justifies the premise.
- Hash-consed path trie (C7b, DR-86): `CostAccountedRho.NativePathTrie` (part 2) models the trie as entries (parent, segment) whose parents precede them and which do not repeat, and proves that two nodes have equal paths exactly when they are the same node (`node_identity_is_path_equality`). Interning keeps every old path and returns the node of the extended path (`child_spec`, `intern_spec`), and ancestors denote path prefixes (`path_of_ancestor`). Decoding a delta chain into the trie accepts exactly the chains that `NativePathDeltaCodec.decode_all` accepts, each returned node denotes the decoded path (`trie_decode_denotes_paths`), and the decode adds at most the total suffix length as nodes (`trie_nodes_bounded_by_suffixes`). A depth-first walk that visits children by increasing segment lists the paths of a sorted tree in strictly increasing lexicographic order, once each, and lists every path (`trie_dfs_is_lex_sort`, `preorder_unique`, `preorder_complete`). A proved negative control shows that a staircase chain of n paths has n new segments but n (n + 1) / 2 materialized segments, which exceeds the journal limit of 262,144 at n = 724 (`materialized_segments_quadratic`, `materialized_segments_exceed_journal_limit`). The model does not verify the Rust jump table or the B-tree of children, which the Rust property tests check against vector computations.
- Aggregated acquisition demand (C8, DR-87): `CostAccountedRho.AggregatedAcquisitionDemand` merges counted rows by key and proves that every key keeps its counted quantity (`aggregate_preserves_counts`, so the expansions are permutations, `aggregate_expansion_permutation`), that the priced value does not change (`aggregate_preserves_weighted_usage`), that the counted discharge and the exhaustion of supply hold for aggregated required and fresh parts exactly when they hold per occurrence (`aggregate_preserves_partition`, `aggregate_preserves_exhaustion`), and that the aggregated keys are distinct (`aggregate_keys_distinct`). Draws that pay each occurrence exactly sum to a draw that pays the aggregated quantity exactly (`aggregated_payment_exact`, from `CountedFundingProjection.join_counted_payments_is_exact`). A proved negative control computes that 2,899 occurrences of eight one-node keys need 5,798 authority nodes for the required and fresh parts, above the limit of 4,096, while their aggregate needs 16 (`occurrence_key_work_exceeds_aggregated`). The model aggregates in first-occurrence order; the Rust demand sorts the keys canonically, which changes no counted quantity.
- Read-coverage of native candidate selection (D-M1 and D-M6, DR-88): `CostAccountedRho.CandidateReadCoverage` reuses the reservation and read events of `ObservationReadCoverage` and proves that a match attempt that only calls the self-metered matcher (`attempt_trace_covered`) and a commit check that only calls the self-metered guard check with a reference vector (`commit_trace_covered`) satisfy prefix coverage, as did the legacy runs (`legacy_attempt_trace_covered`, `legacy_commit_trace_covered`). The attempt performs the same reads as the legacy attempt (`attempt_reads_equal_legacy_reads`) and reserves exactly one pattern inspection and one datum inspection less (`legacy_attempt_excess`); the commit check reserves the continuation inspection, the owned vector and the datum copies less and the reference vector more (`legacy_commit_excess`), and the legacy copies were real work that no longer happens (`legacy_commit_reads`). The new charges do not depend on unread pattern and datum tails (`attempt_charge_independent_of_unread_tails`), on the continuation (`commit_charge_independent_of_body`), or on the sizes of the matched data (`commit_refs_charge_independent_of_matched_sizes`). Proved negative controls compute the legacy excesses (`legacy_commit_charge_depends_on_unread_body`, `legacy_attempt_charge_depends_on_unread_tails`, `legacy_commit_copy_excess`). The model abstracts sizes as natural numbers; the Rust tests check that `get_metered` and `check_commit_metered` reserve their own reads.
- Replay-authority charges (D-O4 and D-O5, DR-89): `CostAccountedRho.ReplayAuthorityPrepareCoverage` models the three branches of a recorded COMM row (retry, granted, frontier) and proves that each branch reserves its own reads and copies before it performs them (`prepare_trace_covered`, `legacy_prepare_trace_covered`), performs the same reads as before (`prepare_reads_equal_legacy_reads`) and reserves exactly the observation walk (granted and frontier) or the authority copy (retry) less (`legacy_prepare_excess`); the granted and frontier charges do not depend on the observation and the retry charge does not depend on the authority (`prepare_charge_independent_of_unread_values`), with the negative control `legacy_prepare_inspects_unread_observation`. `CostAccountedRho.ResultBackingCoverage` proves that the result backing covers every copy that `capture_result` makes in play and in replay (`result_charge_covers_play_copies`, `result_charge_covers_replay_copies`, `legacy_result_trace_covered`), that the copies are unchanged (`result_reads_equal_legacy_reads`), that the legacy charge reserved exactly the events tree, the event payloads and the deep row walks more and the row pointers less (`legacy_result_excess`), and that the charge does not depend on the row payloads (`shared_row_cleanup_releases_no_payload`), with the negative control `legacy_result_charge_counts_unreturned_payloads`. Payload releases prepaid at birth are an explicit modeling premise checked by the Rust allocation test.
- Duplicate-continuation prefilter (D-S4, DR-90): `CostAccountedRho.NativeDuplicatePrefilter` models a waiting continuation's identity (patterns, body, persistence flag, peeks) and its source hash as an arbitrary function of the sorted patterns, the body and the flag, and proves for every such function that equal identities give equal hashes (`identity_eq_implies_source_hash_eq`), that the duplicate decision with the hash prefilter equals the full identity scan (`prefiltered_duplicate_equals_scan`), and that identities are built only for hash ties (`prefilter_builds_identities_only_on_hash_ties`). The negative control `permuted_patterns_share_hash` shows that a hash-only check would be wrong. No collision resistance is assumed.
- Bound-value extraction (D-M4, DR-91): `CostAccountedRho.FreeMapExtraction` models the free map as a sorted association list from levels to bound values and proves that consuming it with a cursor (skip the keys below each level, take the key equal to it) returns exactly the lookups at strictly increasing levels (`extraction_by_move_equals_lookup`), including keys below the first level, between levels and above the last level. `legacy_extraction_charge_quadratic` and the negative control `legacy_extraction_charge_example` show that the legacy per-level inspection and copy was quadratic in the number of bindings.
- Walker block accounting (D-O1 and D-B3, DR-92): `CostAccountedRho.WalkerBlockCharge` models a value as a tree of inline fields, inline entries and memory blocks, and proves for every entry charge `E >= 2p + 2w` and field charge `F >= w` that the walker's reads of the entries inside a block are at most the block's bytes (`visit_reads_le_block_bytes`), that the block charge covers the walk and one consumer traversal (`block_inspection_covers_walk_and_traversal`) and, for a copy, the clone's reads and writes (`block_copy_covers_walk_and_clone`), that every prefix of the walk is covered (`block_trace_covered`), that a copy's backing equals the clone's allocation trace (`block_copy_backing_covers_allocation`), that an inspection fits a copy (`block_inspection_fits_block_copy`), and that the charge does not depend on sibling order (`block_charge_independent_of_sibling_order`). For the chunked worklist it proves that the chunks and chunk headers allocate at most four slots per entry and that the header moves take at most one word per entry (`worklist_charge_covers_peak`, `worklist_charge_covers_entries`, `rust_entry_constant_covers_header_moves`), and that the worklist charge is a function of the number of entries (`worklist_charge_independent_of_traversal_order`). The negative control `level_charge_counts_inline_bytes_per_level`, with `level_charge_example`, shows that the legacy per-push charge counted the inline bytes of nested values once per nesting level.
- Nested prost encodes (D-O6, DR-93): `CostAccountedRho.NestedEncodeCost` models a message as a tree of own bytes and nested messages, prost's length computation as one traversal and its encode as its own bytes plus, for every nested message, the length again and the nested encode. It proves that an encode reads at most `1 + height` traversals (`encode_work_le_height`), that a site that computes the length and then encodes reads at most `2 + height` (`nested_encode_work_le_depth_times_visited_blocks`), and that a block inspection charge `C` that covers one traversal, with `d * C` more for a walk depth `d >= 1 + height`, covers the site (`depth_weighted_charge_covers_encode`). The negative control `linear_charge_undercounts_deep_chain`, with `deep_chain_example`, shows that two traversals do not cover a deep chain. `WalkerBlockCharge.worklist_charge_covers_peak_for_slot` and `rust_depth_entry_constant_covers_header_moves` extend the worklist bounds to the 24-byte entries of the depth walk.
- History decode charge (D-S2, DR-95): `CostAccountedRho.NativeDecodeBacking` models a decoded history record as a tree of inline nodes, vectors, tagged B-tree sets, B-tree maps and strings, and the History-mode decode as a trace of node charges, reservations and allocations. It proves that the decoder's growth reservations are exactly the buffers that RawVec allocates (`growth_reservations_match_raw_vec`, `grown_holds_push`), that every prefix of the trace of a well-formed record allocates at most what it reserved (`decode_charge_prefix_covers`, `decode_charge_covers_allocation`), and that the decoder charges each node once (`single_charge_per_node`). The B-tree premise is cumulative (`twelfth_insert_needs_earlier_slack`): `btree_allocation_within` derives it from the B-tree occupancy invariant through `IncrementalTreeBacking.incremental_prefix_covers_nodes`, and `split_map_tree_covers_joint` shows that the key and value halves of the Rust node size cover the joint node. The negative controls `untagged_set_undercharges` and `box_invisible_undercharges` show that a set under the vector rule and a box leave allocations that no reservation covers. `legacy_byte_array_excess` records the legacy excess: 20,928 bytes of backing for a 32-byte vector that allocates 56 bytes.
- Digest-keyed native store index (D-S1, DR-96): `CostAccountedRho.NativeDigestIndex` models an imbl `OrdMap` as a B+tree with at most 16 entries per leaf and 16 keys per branch, built by inserts only. It proves that a non-root subtree of height h holds at least 5 * 8^h entries and a root branch at least 10 * 8^h (`ord_size_lower_bound`, `ord_root_lower_bound`), that imbl's binary search makes at most 5 comparisons per node (`bsearch_le_5`), and that a search in a tree with at most n entries makes at most 5 * levels_bound n comparisons (`ord_search_comparisons`, `ord_levels_within_bound`, `ord_search_within_bound`, `ord_levels_bound_monotone`, `key_bound_levels`: 7 levels for 2^20 keys). An insert allocates at most 2 * levels_bound n + 2 nodes, including the transient default leaf and the new root of a root split, and a replace at most levels_bound n (`ord_insert_allocations_le`, `ord_replace_allocations_le`). `per_key_schedule_total_invariant` shows that charges that depend only on a key's own history give every schedule that keeps each key's order the same total. The negative control `population_charge_schedule_dependent` shows that a population charge does not, and `legacy_insert_nodes_example` contrasts the legacy insert model (398 nodes at 32 entries) with the bound (16). The TLA+ model `NativeDigestIndexCharge.tla` checks the same schedule independence, with the population mutation as its refuted negative control. For the collision check of D-C2e, the module models the store as a list from digests to entries that hold their key value, with any digest function, injective or not. It proves that the checked lookup returns a value only for the sought key value (`collision_check_found`), that an absent key value has no entry (`collision_check_absent`), and that a reported collision names another stored key value with the same digest (`collision_check_collision`), together `collision_check_preserves_key_semantics`. `insert_checked_keyed` shows that the checked insert keeps every entry under the digest of its own key value, and the negative control `unchecked_lookup_returns_another_key` shows that a lookup without the check returns the value of another key under a constant digest.
- Dirty-key native export (D-S3, DR-97): `CostAccountedRho.NativeDirtyExport` models the stored leaf of a value as its encoded rows, sorted, and a cold fill as the decode of those rows. With an encoding that is stable under decode and encode, a cold fill re-encodes to the stored leaf, and an empty value to no leaf (`leaf_reencodes`, `clean_cold_fill_round_trips`, `written_history_fills_round_trip`); the premise control `unsorted_leaf_reencodes_differently` shows that the sortedness of stored leaves is needed. Over a history modelled as a map from keys to leaves, writing the value that a key holds keeps the map (`update_idempotent`), so for a store with distinct keys whose clean entries hold history values the dirty export and the full export give the same map (`dirty_export_equals_full_export`). Cold fills, writes, checkpoints and restores keep that property (`dirty_invariant_preserved`), so the two exports agree in every reachable state (`reachable_dirty_export_equals_full_export`). The negative control `write_without_dirty_changes_root` shows that a write that keeps the clean flag makes them differ. The TLA+ model `NativeDirtyExport.tla` checks the same agreement, with the write-without-flag and restore-drops-flags mutations as its refuted negative controls.
- Offered-only activation refinement: `CostAccountedRho.OfferedOnlyActivation` proves that active admission rejects body-only deploys, active selection is independent of block height, selected and published user deploys are offered-funded, and active validation rejects any body-only deploy. The Rust admission, proposal, and replay tests check that production follows this model.
- Policy-gated version adoption: `CostAccountedRho.GenesisVersionAdoption` proves that only a policy-carrying approved genesis adopts the approved header version, that a legacy genesis keeps the local version, that an adopted version passes the policy version check while an unadopted mismatch fails it, and that the adopted version does not depend on node-local configuration. The Rust property tests check `adopted_casper_version` and the real `GenesisResourcePolicy::adopt`.
- Native path delta codec: `CostAccountedRho.NativePathDeltaCodec` proves, for any segment type with decidable equality, that the delta encoding of a path chain round-trips and that every accepted encoding is the encoder's output, so each chain has exactly one encoding.
