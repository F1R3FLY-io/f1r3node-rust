## Findings

1. The RGB path now executes on Rholang and RSpace++. ADR-0002 in Rholang-RGB replaces ALuVM with Rholang. The note still describes RGB as a separate machine B with a client-side ALuVM-style contract machine.
2. WS5 adds a Byzantine fault tolerant peer-clique medium with per-transaction commits, epoch-based membership (`committee_root`), and quorum certificates. The note lists only a seal medium for RGB.
3. Bitcoin single-use-seal anchoring follows a clique commit. Anchoring is a separate step after finality, not the ordering medium itself.
4. Peer-clique question 21 (section 6.6) asks what the shard framework expects as the commit product. Question 22 asks which callbacks connect the engine, the Rholang executor, RSpace++, and the data plane. The boundary design must answer both questions.
5. A multi-parent block (CBC Casper, Casanova, Cordial Miners) and a per-transaction commit (peer clique) both fit one commit abstraction. The abstraction has a pre-state, a deploy set, a post-state hash, and opaque mechanism evidence.
