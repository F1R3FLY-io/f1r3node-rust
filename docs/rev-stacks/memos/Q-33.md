# Q-33: P11 in v6, no block is final until its state is known (revision 2)

This revision answers lane A1's review of revision 1 (`1c0256324`): items Q1 to Q5, the answers to the FX-17 paper's three questions, and conditions 1 to 4 on FX-17. The storage and transaction layout is in `FX-17-order-floor-storage.md` (`d3df10dd3`). This memo refers to that paper and does not repeat it.

## 0. Terms

- **Order floor (OF):** the oracle's `Advance(F)` after every guard that today's LFB passes: P1 to P4, containment and A-LIN. `NotHigher`, containment and `derived_against` are checked against the order pointer. The finalizer's σ folds in the order pointer.
- **Canonical frontier (CF):** the last linear position with a fixed canonical record (`ExecutorCore::canonical_len() − 1`).
- **LFB:** the state-final block. It is a main-chain prefix of the order floor, and P5 moves it.
- **Order-final:** a status name for clients, if one is wanted. "Finalized" means state-final only.

The ordering is always LFB ≤ CF-block ≤ OF in the linear order. The LFB needs attested canonical roots, so it cannot pass CF.

## 1. Execution (unchanged from revision 1, with Q1 fixed)

The linearizer follows the order floor. `ExecutorCore` executes the certified prefix above the LFB.

**Q1, the stall (fixed in the FX-17 paper):** the order floor commits on the oracle's certification alone, in the order part of `commit_floors`. P5 moves only the LFB, and a state-only call runs in each cycle. Neither pointer waits for the other.

## 2. Finality

**The rule:** P5 holds at position p iff the stake behind attestations that support p is more than 2/3 of the bonded stake.
- An attestation `(j, root)` supports every p ≤ j iff `root` equals the local canonical post-root at j. The canonical records fix the state of the prefix, so one match covers every earlier position. (Lane A1's condition 4 corrects revision 1's wording here: under Decision 89, play is not deterministic.)
- **One bond set for each check:** each computation of p* uses the bonds at the LFB of that computation and no other set (lane A1's answer 2).
- Under θ ≤ 0, there is no P5.

## 3. Q2: gates and their floors

| Gate | Measures | Engages when | Action |
|---|---|---|---|
| Lag gate (`LagGate`) | OF − CF | above `lag_threshold` | proposals carry no envelopes |
| `max_unattested` | OF − LFB | above `max_unattested` | proposals carry no envelopes |
| Floor pacing (`floor_pacing_engaged`) | newest block − OF | above `proposal_pacing_floor_distance` | proposals carry no envelopes |

- **Lag gate:** `admits_envelopes` measures `Lag::measure(number(OF), number(attested canonical block))`. Today it reads the LFB, so under P11 the lag would always be 0 (lane A1, Q2). With OF, bound E of the stall analysis holds again: the execution backlog OF − CF is limited to `lag_threshold` blocks with envelopes, plus empty blocks.
- **Floor pacing** goes to the order floor. Floor pacing paces proposals against the order oracle, as it does today, where LFB and order were one floor. The finality lag (OF − LFB) is `max_unattested`'s, so no lag is counted twice.
- Each gate reads its floor once for each proposal, from the same snapshot.

## 4. Q3: void records

### The void predicate

`void_reason(block, pre)` is a function of the block and the canonical pre-state at the block's linear position, and of nothing else. Here `pre` is the canonical post-root of the position before. Every executor and every replay computes it.

| # | Outcome | Decided from | Void? | Slashable (Decision 101) |
|---|---|---|---|---|
| V1 | The proposer's free balance at `pre` is less than `close-precharge`. The hold is taken before any envelope, so the gate table is empty at that point. | `pre`, policy | Yes | No. It is recorded, not slashed: the proposer cannot see `pre` when it proposes. |
| V2 | The block carries slash records before B6 (`require_no_slashes`, today an execution error that stops the engine) | block | Yes | Yes. The proposer wrote them. |
| V3 | An envelope's terms cannot form gate inputs (`gate_inputs` error, today an execution error) | block | Yes | Yes. It is visible in the block. |
| V4 | The close fails (`UnexpectedSystemErrors`, `ConsumeFailed`), today an execution error | `pre`, block | Yes | No. It is not visible from the proposer's justifications. |

**Not void:** every envelope-level outcome gives a normal record. This covers gate refusals, `UserFailure`, `Exhausted`, membrane stops (FX-15) and `NotRun`.

**A void record:**
- post-root = `pre`;
- each envelope has outcome `Voided`;
- no settlement and no close;
- `void_reason` is in the record entry.

**Effect:**
- V1 to V4 stop being errors that halt the engine.
- An execution error that remains after this table is a node fault, not a block fault. The node stops and does not write a record, as today.

### Replay checks in both directions

`BlockExecutor::replay` computes `void_reason(block, pre)` first.

| Record | Predicate | Replay |
|---|---|---|
| void | `Some(r)` with r equal to the recorded reason | accept, root = `pre` |
| void | `None`, or a different reason | **reject**: a void record for a valid block |
| normal | `Some(_)` | **reject**: a normal record for an invalid block |
| normal | `None` | normal replay |

### Faults of the attester or the citer (the block stays valid)

| Fault | Who | Evidence |
|---|---|---|
| A void record for a valid block, or a normal record for an invalid one | the citer | `InvalidRecord { reason: Replay }` |
| A failed Decision 89 check (an early stop, a forged D, an unpayable admission, a forged step) | the citer | `InvalidRecord { reason: Replay }` |
| Any other mismatch of roots, entries or settlement | the citer | `InvalidRecord { reason: Replay }` |
| A record whose envelope list differs from the block | the citer | `InvalidRecord { reason: Envelopes }` |
| An attested root that differs from the canonical root | the attester | `Misattestation` |
| An included envelope that the gate refuses at the proposer's attested root | the proposer | `InclusionViolation` (not void) |

A citer fault dismisses that record. The next citation of the same block is tried, as today (`dismiss`).

## 5. Q4: slashing (Decision 101)

- `Offence::VoidBlock { reason, slashable }`.
- `slashable` is true only for reasons that the proposer could decide from its own justifications: V2 and V3.
- V1 and V4 are recorded and not slashed.
- B6 reads the flag.

## 6. Q5: re-inclusion

**Rule:** an envelope in a void block counts as not included.

- **Repeat check:** for a v6 block, `repeat_deploy` at acceptance cannot decide this. The earlier carrier may not be executed yet. The check therefore moves to execution:
  - The gate refuses an envelope whose signature appears with a non-`Voided` outcome in a canonical record at an earlier position, inside the deploy lifespan. The refusal is new: `Refusal::AlreadyIncluded`.
  - That is a function of the canonical records before the position, so replay computes the same refusal.
  - At acceptance, `repeat_deploy` skips v6 envelope signatures and keeps its other checks.
- **Inclusion check:** the inclusion screen at the proposer's attested root uses the same rule. An envelope already run in a non-void canonical record at or below the attested position is an `InclusionViolation`. An envelope whose only carriers are void is not.
- **Deploy index and status:** the carrier index records the carrier as today. Status readers skip `Voided` outcomes, so a deploy whose carriers are all void is "pending", not "included".
- **Charge once:** a void record charges nothing, because post = pre. The block that finally runs the envelope charges it. A later carrier is refused (`AlreadyIncluded`) at no charge.
- **Pool:** at a void record, the node puts the envelopes back into its deploy pool and removes their rejection entries.

## 7. FX-17 conditions

### Condition 1: each LFB consumer to one floor

| Consumer | Floor |
|---|---|
| `V6Engine::tick` (linearizer), A-LIN hold | OF |
| Finalizer σ, `NotHigher`, containment, `derived_against` | OF |
| Lag gate | OF and CF |
| Floor pacing | OF |
| `max_unattested` | OF and LFB |
| P5 bond set, `bond_cache` | LFB |
| Deploy status, `deploy_lifecycle`, `block_api` "finalized", `BlockFinalised` events | LFB |
| `last_finalized_height_constraint_checker`, `synchrony_constraint_checker` | LFB |

| `graph_generator`, `soak_snapshot` | both, labelled |

FX-17 starts with a code search for `last_finalized_block()`, `lfb_pointer()` and `last_finalized_block_hash`. Each call site gets a comment in the code review (not in the code) and a row in this table.

### Condition 2: restart

- The linearizer resumes from the order pointer and the persisted canonical frontier (`RecordStore::canonical_len`), not from in-memory state.
- The attestation tally is rebuilt from the bodies of the blocks above the LFB.
- The startup invariant is height(OF) ≥ height(LFB).

### Crash test

- A node commits the order floor and crashes before an LFB commit.
- After restart:
  - the order pointer and the canonical frontier are as before the crash;
  - the linearizer emits nothing twice;
  - the tally gives the same p*;
  - the next state-only call moves the LFB.
- A second case crashes between `batched_put` and the in-memory swap.

### Condition 3 (lane B)

The close of a void block does not run. Lane B confirms:
- PoS starts an epoch at the first block at or above the boundary;
- each per-block close duty is deferred to the next close that runs.

## 8. Tests for FX-17

1. P5 with three validators, and with one misattesting validator (more than 2/3 of the stake still final; misattestation evidence).
2. Lag gate engages on OF − CF. `max_unattested` engages on OF − LFB.
3. One test for each of V1 to V4: play gives a void record, and replay accepts it.
4. Trace alteration: a void record for a valid block is rejected. A normal record for a V1 block is rejected.
5. Re-inclusion: an envelope from a void block runs once in a later block and is charged once. A third carrier is refused with `AlreadyIncluded`.
6. Crash tests (section 7).
