# P3-01 decisions: the COMM bound of Delta

Patch P3-01, "delta_sigma estimator", rev-stacks patch plan r6.4, lane C.
Branch `patch/P3-01`, cut from `patch/P2-19`.

## Ruling

Ruling of 2026-10-30: re-implement only the COMM bound, after P2-18. Port
nothing. The source's `accounting/delta_sigma/*` (b5f5406e0 and the earlier
B1/B2 commits) is not ported. This patch is new code.

## Decisions

| # | Decision | Alternatives | Reason | Reversible |
|---|----------|--------------|--------|------------|
| 1 | `accounting::delta_sigma::comm_bound(term)` returns `Some(n)` only for a closed, linear term. In such a term every send and every receive is on a name of a plain `new` of the term, no send or receive is persistent, no process variable or method call runs in process position, and there is no token stack. Otherwise it returns `None`. | Count all sends and receives of any term, as the source does for its signed regions. | In this design every COMM of an envelope's run is charged to the envelope (P2-05). A send on a public channel or a URN can meet a stored persistent receive whose body runs in the same envelope, so the term alone cannot bound the COMMs. A private name cannot leave the term, because every send of the term is on a private name. | Yes |
| 2 | For a closed, linear term, the bound is the number of receives that can run: a receive adds 1 and its continuation; `match` and `if` take the largest branch; `new`, `bundle` and signed-term bodies add their bodies. Sent data adds nothing. | Count sends too. | A non-persistent receive takes part in at most one COMM, and a join is one COMM. A continuation runs at most once, because its receive is linear. Data runs only through a process variable, which decision 1 excludes. | Yes |
| 3 | Names bound by a receive or a match case are not private. | Track private names through the data. | This is conservative. It returns `None` for reply-channel patterns such as `for (r <- x) { r!(1) }`. | Yes |
| 4 | `DeltaEstimate { comm, compute }`, with `delta(phlo_limit)`. `compute` is always `None` until Q-24, so `delta` is `phloLimit` in practice, as the design says ("The life of an envelope"). | Wire the bound into the gate now. | The plan: "the compute part stays bounded by phloLimit until a static compute estimate exists (Q-24)". The gate wiring also needs P2-04 and Q-24. | Yes |

## Tests

`rholang/tests/delta_sigma_spec.rs`:

- `the_bound_covers_every_comm_of_the_corpus`: for 10 closed terms, the bound
  is the expected number, and the run's COMM ledger (P2-05) never exceeds it.
- `unprovable_terms_have_no_bound_and_delta_falls_back_to_the_limit`:
  contracts, persistent receives and sends, public channels, URN channels,
  process variables, leaked names and token stacks give `None`, and `delta`
  is `phloLimit`.
- `delta_never_passes_the_phlo_limit`.
- `generated_closed_terms_never_exceed_their_bound`: a property test on 64
  generated closed terms (sends, receives, joins, `if`, `match`, nested up to
  depth 4) runs each term and checks that the COMM count stays within the
  bound.

## Open items

1. **Gate wiring.** Use `DeltaEstimate::delta` in the gate when Q-24 gives a
   compute bound. Until then, it would change nothing.
2. **Reply channels.** Decision 3 could be relaxed with an analysis of where
   names flow. It is not needed while `delta` is `phloLimit`.
