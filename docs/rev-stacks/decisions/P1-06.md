## Decisions

| # | Decision | Alternatives | Reason | Reversible |
|---|----------|--------------|--------|------------|
| 1 | "Record format without system logs" (the brief) is read as: no settlement system logs in the record (the wallet log and receipt log of the integration branch's record). The P1-04b `BlockRecord` already has none. The close-block `ProcessedSystemDeploy` stays in the record, because replay of the close block needs its log. | Drop the close-block system deploy and re-play it on replay. | The close block is dev's PoS system deploy, not settlement. Replaying without its log would trust a play to be deterministic. | Yes |
| 2 | **Pending (memo E).** dev's Merkle block hash covers `body.extra_bytes` but not the new `body.v6`. When `body.v6` is present, its canonical encoding enters the header preimage after `extra_bytes`, behind a marker byte (0x16) and a little-endian u64 length. A body without `v6` hashes exactly as on dev (the golden hash test is unchanged). | Keep records in `extra_bytes` (do not move them). A separate Merkle leaf for the v6 body. | Without it, the attestation and the records sit outside the signed block hash after 0029. On the integration branch's base the whole body was hashed, so 0029 did not need this. | Yes, before any shard launches |
