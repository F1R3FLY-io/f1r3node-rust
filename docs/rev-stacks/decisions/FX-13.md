# FX-13 decisions: received data runs under the continuation's membrane

Fix FX-13, Decision 77, design revision 10 §6.3, rev-stacks patch plan r8.9,
lane C. Branch `patch/FX-13`, cut from `patch/FX-8b` (1c281b7a0), the FX

## Rulings used

- Decision 74 (design r10 §6.3): two elaborated forms define cost
  accounting. Two parties: `{% for(ptrn <- chan){% P %}[t] %}[s1] | {% chan!(Q) %}[s2]`.
  One party: `{% for(ptrn <- chan){% P %}[t] | chan!(Q) %}[s]`. A
  continuation not in its own membrane uses the enclosing seal.
- Decision 77: the `from_data` mark is removed, with the native refusals under
  it. Received data runs under the continuation's membrane. Origin
  verification (Decisions 52, 53, 63) stays.
- Decision 71 is superseded. The workaround it documented (pass the received
  process to a separate receive) is not needed and is not on this branch.

## Conformance tests

`rholang/tests/seal_record_spec.rs`: the 11 route tests now show that data received along each route runs under the continuation's membrane (Alice's, the code that stored the receive) and is paid there. Each route runs six payloads that Bob sends:

| Payload | Expected |
|---|---|
| `{% slot :: () %}[a]`, with `a` Alice's id | runs; one unit from Alice to the slot |
| `{% slot :: () %}[b]`, with `b` Bob's own id | refused by the origin check; no wallet changes |
| `slot :: ()` | runs; one unit from Alice (the membrane) |
| `{% slot :: () %}[k]` (a kind mint) | runs; the slot holds one unit of the kind |
| `rho:rev:wallet` transfer of 100 from `a` to Bob | runs; Alice 900, Bob 1,100 |
| `rho:rev:bond` bond of 100 by `a` | runs; Alice 900, bond 100 |

The routes are those of the FX-6 route coverage (drop of a received name; a received process variable; a method result; a received value in a stored receive that fires later; the same in a contract; data out of the tuplespace through a peek; a persistent send; a match binding; a received process inside the owner's own region; `new`, `if` and bundle bodies; a continuation stored by received data).

Other tests:

- `a_seal_inside_data_received_at_run_time_draws_on_no_wallet` is removed. The route tests replace it.
- `a_kind_minted_inside_data_still_mints_and_a_received_kind_name_still_moves_in_code` is unchanged.
- The origin-verification tests are unchanged: `a_foreign_seal_in_a_later_runners_own_code_is_refused`, `a_region_sealed_in_its_origin_runs_for_a_later_runner_and_pays_from_its_sealer`, `a_stored_continuation_carries_its_authors_record`, the FX-3 cosignature tests (`a_lifted_cosignature_carries_no_authority_under_another_deployer`, `a_stripped_envelope_does_not_decode_and_the_complete_envelope_runs_after_it` and the `casper_message` unit tests) and the second-encoding test.
- `rholang/tests/seal_wiring_spec.rs` (lane B and lane A2 tests, in the native commit): a wallet or bond call inside received data now acts under the receiver's membrane, and a `rho:rev:bondAdmin` call inside received data acts with the name it carries.
- `casper/tests/v6/region_spec.rs`: `data_sent_to_an_owners_contract_runs_under_the_owners_membrane_and_is_paid_there` replaces the FX-6 refusal test. Alice's stored contract runs Mallory's sealed stack, two units move from Alice to the slot, Mallory pays only her own charge, and the block replays to the same settled root.

## F33

Decision 75 locates the purse that pays a stored receive at its surface, and every draw on a located purse is admitted move by move against balance less commitments, checked for overdraw at the close of the run (Decision 48), and admitted cumulatively across the block (Decision 49). Gate commitments then bound only the client's own part. A variable seal that resolves at run time to a cosigner's wallet draws on that located purse under the same admission, so it needs no commitment of its own. With located purses, F33 is moot. The ruling stays with Q-31.
