# FX-18, the validator-set handoff at each epoch close (lane B)

Base: `patch/FX-16` at bed78053e (which contains `patch/FX-17-epoch` at 30258ed83). Branch `patch/FX-18-handoff`. Lane A2 owns the attestation format and the join path. The format proposal to lane A2 is in [the FX-18 handoff memo](../memos/FX-18-handoff.md).

Names: V1…Vn are validators, B1…Bj are blocks. R(e) is the handoff record of the committee that serves in epoch e.

## Decisions

1. **One-epoch lookahead.** The set that serves in epoch e + 1 is picked at the close that starts epoch e.
   - Reason: the validator set of a block is the committee at its attested root. Without the lookahead, the new set is written into a root that only the new set attests, so the outgoing set never certifies it.
   - Effect: a bond serves one epoch later than before. A withdrawer serves out the epoch that its record names.
   - **Flagged for review.** It changes when bonds and withdrawals take effect. It does not change the epoch counter (Decision 105) or the release schedule (Decision 114).
2. **The record is the Rholang triple `(previous, active, bonds)`, stored as `toByteArray` bytes.** The hash is Blake2b256 of the stored bytes. A verifier hashes and decodes the bytes that it receives, so no canonical re-encoding is necessary.
3. **The record carries all bonds, and Rust restricts them to the active set.** A restriction in Rholang is a fold over the active set at every epoch close.
4. **The records live on a private channel, `handoffCh`.** Only genesis and the close that starts an epoch write it, so bond and withdraw calls do not pay to copy the records.
5. **The v6 validator source reads the current record** (`committee_at`). Consensus and a joiner then count the same stakes, and the stakes are fixed for the epoch.
6. **The pre-charge counts the bonds that the records carry.** `close_charge::charged_bonds(rm, root)` is the greatest of: the bonds at the root, the bonds in the current record, and the bonds in the next record.
   - Reason: the close copies the records. After many withdrawals, the records hold up to two epochs more bonds than `allBonds`. The 99-withdrawer case at epoch 2 cost 229,562 phlo against a pre-charge of 213,000 for one bond.
   - This refines Decision 113 (bonds at the true pre-state): the records are part of the pre-state. **Flagged for review.** No production caller exists yet. Lane A2's close wiring must call `charged_bonds`.
7. **The verifier counts each signer once, counts only members of the held committee, and requires more than θ of its stake.** It refuses a record whose `previous` is not the hash of the held record.

The records add about 1,100 to 1,900 phlo per carried bond to an epoch close (two records are copied, one is encoded and hashed). The rate of 13,000 per bond covers it. The smallest margin is 1.47, in the 99-withdrawer case at epoch 1.

## Known issues

Each item has a Decision 88 label.

1. **`slashing_authorization` derives epochs by arithmetic and can reach behind the fringe.** It computes the epoch of a block from its number, not from the PoS epoch counter, so after a void boundary it can disagree with PoS. To check a slash against an old epoch, it needs state at that epoch, which P12 does not keep. **Known issue:** the code is not used before B6. B6 must read the epoch from the record chain (each record names its predecessor) or from the counter at a root above the fringe.
2. **A slash does not change the records.** `slash` zeroes the bond and removes the key from the live `activeValidators`. The current record still holds the key with its stake for the rest of the epoch, and the next record holds it when it was picked. The records cannot change during an epoch, because the next record's hash is what the attestations certify. **Known issue until B6:** v6 runs no slashing. B6 must decide whether a slash takes effect at the next pick, or whether the next record is rebuilt (and its certificate starts again).
3. **A withdrawer can be released while it serves.** The quarantine end is `q + L × (1 + n / L)`, with n the block of the withdrawal. Releases run only at epoch closes. With the lookahead, a withdrawer serves the epoch after its withdrawal. If the close that starts that epoch comes q or more blocks after the boundary (or q = 0), the same close releases the stake. **Known issue until B6:** the released stake cannot be slashed while it still counts in the committee. One fix is one more epoch in the quarantine end, `q + L × (2 + n / L)`. That changes the Decision 114 schedule, so it is a question for Meredith.
4. **The engine's fallback reads live bonds.** When the validator source fails, `engine.rs` uses `snapshot.on_chain_state.bonds_map`, which is not the record committee. **Known issue for lane A2:** a failed read should stop the proposal, not change the stakes.
5. **The attestation does not carry the handoff hash yet.** The record and the verifier are in place. The certificate needs lane A2's field and validity check (memo, items 1 to 3). Until then, nothing certifies a record on the wire. This is part of P12-2 and is blocking there, not here.
