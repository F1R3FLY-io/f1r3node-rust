# Decisions — P0-10 (A4, reduced: verify once, one buffer read, cap under the guard)

Each entry gives the decision, the alternatives, the reason and whether it is reversible.

## D-P0-10-1 — Port 600689764 on top of dev's single pool read

- **Decision:** The cherry-pick of `600689764` keeps dev's `create_with_progress` structure. dev already reads the pool once per proposal (`30453da91`, `23dc2cd53`). The patch adds only the buffer half of Track A's `PoolSnapshot`, as `BufferSnapshot` (`deploys`, `sigs`). `fresh_local_deploy_stats`, `in_scope_local_deploy_stats` and `rejected_buffer_has_recoverable_deploys` take it in place of the buffer mutex.
- **Alternatives:** Port `PoolSnapshot` whole. It reads the pool under a pool mutex, which dev removed in `f1bc683d5`.
- **Reason:** Prefer dev's code over ports. The proposal path read the buffer three times before this patch and reads it once now.
- **Reversible:** yes.

## D-P0-10-2 — prepare_user_deploys_with_policy keeps its own buffer read

- **Decision:** The prepare step still reads the buffer itself.
- **Alternatives:** Pass the snapshot into the prepare step.
- **Reason:** Track A kept this read too. The prepare step removes expired and floor-settled entries from the buffer, so it must act on the current contents. `BufferSnapshot::read` keeps dev's O(1) `non_empty` check, so an empty buffer costs no `read_all`.
- **Reversible:** yes.

## D-P0-10-3 — Pool cap under the rejected-buffer guard

- **Decision:** `reserve_deploy` returns `Reservation::{Added, Duplicate, PoolFull}`. It checks `pool_admission` after it takes the rejected-buffer guard and before `add_if_absent`. This answers P0-00 confirmation item 5 with the recommendation.
- **Alternatives:** A pool mutex, as in Track A. dev has none.
- **Reason:** The rejected-buffer guard serializes admission on dev (claim S4 in `docs/claims/deploy-store-concurrency.md`). The check and the insert are atomic under it. The P0-09 check in `admit_deploy` stays as a fast path before the parse, as in Track A.
- **Reversible:** yes.

## D-P0-10-4 — Verify-once cache size is configuration

- **Decision:** Track A hard-coded 262,144 entries. The patch adds `casper.deploy-verified-encodings-cap` (default 262,144). The node sets it at start-up, before it opens the deploy storage. The value 0 turns the cache off. The cache is process-wide, as in Track A, because the codec has no node context.
- **Alternatives:** A field on the deploy storage. The codec functions are plain function pointers in the typed store, so they cannot carry state.
- **Reason:** Caps and limits are configuration parameters.
- **Reversible:** yes.

## D-P0-10-5 — Verify-once is not an authority change

- **Decision:** No escalation.
- **Reason:** The cache holds the Blake2b-256 hash of payload bytes whose signature this process verified. Only identical bytes skip the check. Different bytes hash differently and get the full check (test `a_verified_encoding_is_trusted_on_later_reads_and_nothing_else_is`). Block validation does not use this path. It verifies deploy signatures in the block itself.
- **Reversible:** yes.

## D-P0-10-6 — Tests from c4b8b40c4, adapted

- **Decision:** The two `PoolSnapshot::read` tests become `BufferSnapshot` tests, with their source comments. One test for an empty buffer is added. The drive-bys in `c4b8b40c4` are not ported: the clippy fix is in A8 code, the `ALinPolicy` allow is not needed, and the `Cargo.lock` and `deny.toml` changes are on dev.
- **Reversible:** yes.

## Done-when measurement (release build, in-memory store, mean of 3 reads)

| Pool size | `read_all`, verify on every read | `read_all`, verify once |
|---|---|---|
| 500 | 47.6 ms | 0.85 ms |
| 1,000 | 85.4 ms | 3.3 ms |
| 2,000 | 191.4 ms | 4.4 ms |
| 4,000 | 273.2 ms | 17.0 ms |

The signature check was more than 95 % of the read cost. The read is still linear in pool size, because `read_all` decodes every entry. So the prepare time is not flat in pool size. It is 15 to 50 times lower. The pool cap from P0-09 bounds the pool size. The soak must confirm the result on LMDB.
