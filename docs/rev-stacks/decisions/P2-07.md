# P2-07 decisions: price floor and node price hook

Patch P2-07, "Price floor and node price hook", rev-stacks patch plan r7.2,
lane B. Branch `patch/P2-07`, cut from `patch/P2-04`. All code in this patch
is new. Nothing is ported.

## Files touched

- `casper/src/rust/v6/validity.rs`: `Limits.min_phlo_price`, `Limits::with_floor`, and the floor check in `check_structure`.
- `casper/src/rust/v6/resource_policy.rs`: `limits()` sets the floor field to 0.
- `casper/src/rust/v6/propose.rs`: one test literal gets the new field.
- `casper/src/rust/v6/engine.rs`: the price hook field, `set_price_hook`, and the effective price in `create_block`.
- `casper/src/rust/v6/price.rs`: new.
- `block_creator.rs` is not touched. The v6 proposer is `V6Engine::create_block`, so lane A1's P0-01, P0-09 and P0-10 do not meet this patch.

## Decisions

| # | Decision | Alternatives | Reason | Reversible |
|---|----------|--------------|--------|------------|
| 1 | The shard floor is dev's `min-phlo-price` consensus parameter, which PoS holds from genesis. The node adopts the on-chain value at startup (`read_on_chain_consensus_parameters`). A second copy in `ShardResourcePolicy` is not added. | Add the floor to the policy encoding (version 2). | Prefer dev's code. dev's floor is already a genesis value and the consensus input to block validity step 8. Two sources could disagree. | Yes, before any shard launches |
| 2 | A v6 block with an envelope priced below the floor is invalid: `check_structure` refuses it. The floor comes in `Limits.min_phlo_price`. The default is 0. `Limits::with_floor` sets it. | A separate validity step. | The v6 validity path is `check_structure`. dev's `Validate::phlo_price` does not run on v6 blocks. | Yes |
| 3 | `V6Engine` constructors keep `Limits::default()` (floor 0) and their signatures. The engine wiring (P1-01 round 2 / P2-05) passes `policy.limits().with_floor(shard_conf.min_phlo_price)`. | Change `V6Engine::new` now. | No caller constructs the engine yet. The wiring is a hook point in `casper.rs`. | Yes |
| 4 | The validator's acceptance price goes through `PriceHook`. The first version is `FixedPriceHook`, built from `NodePriceConf { fixed-price }` (kebab-case, default 0, refused if negative). | A constant. A field in `CasperShardConf` now. | Design §6.2 and Decision 5. A field in `CasperShardConf` needs 17 literal changes in other lanes' files. The node configuration key is added when the engine is wired (hotspot shared with P1-09, P1-12 and P2-05). | Yes |
| 5 | The proposer selects envelopes at `max(hook price, shard floor)`. The node never accepts below the floor, whatever its own price. | Use the hook price alone. | The floor is a validity rule. A block below it would be refused. | Yes |
| 6 | The hook is held as `RwLock<Arc<dyn PriceHook>>` on the engine, with `set_price_hook`. | A constructor argument. | Making pricing programmable later is a change to the hook only (§6.2). The engine is built once and shared. | Yes |
| 7 | Decision 26: the floor is not scaled by the number of signature components. The check compares the deployment's `phloPrice` with the floor once per deployment. | — | Decision 26 (minimum coordination cost). Phase 2 has no compound signatures. The check does not change in phase 3. | — |

## Tests

- `v6::validity::tests::an_envelope_below_the_shard_floor_makes_the_block_invalid`: at the floor and above passes, one envelope below fails, and floor 0 passes.
- `v6::price::tests`: the fixed hook returns the configured price and refuses a negative one. The effective price is never below the floor. The configuration reads kebab-case keys and takes the default when a key is missing.
