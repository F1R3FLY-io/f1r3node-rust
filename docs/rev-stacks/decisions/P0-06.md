# Decisions — P0-06 (A1b: time only the derivation)

Each entry gives the decision, the alternatives, the reason and whether it is reversible.

## D-P0-06-1 — Build on a local stack of P0-04, P0-02 and P0-05

- **Decision:** `patch/P0-06` starts at `patch/P0-02` (which contains P0-04), with the two P0-05 commits applied on top. The P0-06 commits are the commits above `docs(rev-stacks): P0-05 decision record`.
- **Alternatives:** Cut from the phase branch and wait until P0-04 and P0-05 land there.
- **Reason:** P0-06 depends on P0-04 and P0-05, and the phase branch contains neither. Agents do not push to the phase branch.
- **Reversible:** yes. The P0-06 commits rebase onto the phase branch when P0-04, P0-02 and P0-05 land there.

## D-P0-06-2 — Re-implement 5d78f252c on dev's finalizer task

- **Decision:** `run_cycle` takes three steps: `derive` (under the timeout), `commit` (untimed) and `after` (untimed). `derive_last_finalized_block` makes the LFB decision and computes the fault tolerance of an adopted floor. `adopt_derived` commits through `record_directly_finalized` and `commit_lfb` and runs the finalization effects. `adopt` takes the fault tolerance as an argument.
- **Alternatives:** Cherry-pick `5d78f252c`.
- **Reason:** `5d78f252c` changes `drive_finalizer_runs`, which dev removed in `3a455a679`. Its split is kept: the timed step writes nothing, and the commit is never cancelled. As in Track A, the fault-tolerance value is in the timed step because it is an oracle computation.
- **Reversible:** yes.

## D-P0-06-3 — The cycle-time metric still covers the whole cycle

- **Decision:** `FINALIZER_RUN_TIME_METRIC` records the time of derivation and commit together, and `FINALIZER_RUN_TIMEOUTS_METRIC` counts derivation timeouts.
- **Reason:** Dashboards read the cycle-time metric as the time of one cycle. Only the timeout now applies to a smaller part of the cycle.
- **Reversible:** yes.
