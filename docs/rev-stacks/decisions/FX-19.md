# FX-19 decisions (lane C): the declared per-firing bound

Branch `patch/FX-19`, cut from `patch/FX-17` at 0b01b1663. Design: Decisions 120, 124, 125 and 126. Memo: `docs/rev-stacks/memos/FX-19-declared-bound.md`. Names: u1…um deployers, d1…di deployments, B1…Bj blocks. W is a wallet.

## 1. What is built

| Part | Code |
|---|---|
| The seal record carries the installing deployment's phlo limit | `SealOrigin.phlo_limit` (field 4), `Origin::phlo_limit`, `system_processes::DeployData::phlo_limit`, set from the signed deployment |
| A firing | `dispatch.rs`: a stored continuation whose seal record the meter gates runs in a `membrane::Firing` scope |
| The buffer | `reduce.rs`: in a firing, `produce_inner` and `consume_inner` charge the issue cost (storage and the reservation of c97c2e4b3) to the firing and keep the operation. The operations go to the tuple space when the body's evaluation ends. |
| The bound | `Firing::charge` adds each charge and its reservation to the firing's cost. When the cost passes `phlo_limit`, the firing is exhausted: its buffer is discarded, every later charge in it fails, and W pays `phlo_limit` at the record's price. |
| The match filter | `seal::admits_comm` in play, and `charging_rspace::hold_replayed_comm` for each COMM in replay. Both call `MembraneMeter::hold`. |
| The share | `EnvelopeFunding::limit` = free(W) / n. n is the number of envelopes that the gate admitted (Decision 125). `CloseFunding::limit` = free(W) less what the runs held. |
| Removed | `StepScope`, step identities, `Refusal`, `ReplayRefusals`, `Admission`, `BlockLedger`, `admits_waiting`, the follow-up scope, `accept_metered`, `replay_with_refusals`, `v6/stops.rs`. Play and replay use the same check. |

## 2. Decisions taken in the build

| Decision | Alternatives | Reason | Reversible |
|---|---|---|---|
| The wallets that a firing holds are the purse of the stored continuation's seal and the owners that the stored body names statically (`region::resolved_owners`, which also resolves `# P` seals). Each holds the bound. | The purse and every signer of the installing deployment (the first draft) | A `# P` contract pays from its own wallet. With the signers, its installer had to hold the bound too, and a contract with an empty installer could never fire. Decision 124's second example is covered: `{% P %}[t]` in the body names t, so t holds the bound. | Yes |
| The continuation's purse also holds the COMM's own charges: one cell and the COMM event storage. Each gated datum holds one cell. | Hold the bound only | These charges are drawn at the COMM, outside every firing. Without a hold they could overdraw W. | Yes |
| A charge inside a firing to a wallet that the firing does not hold exhausts the firing | Charge it without a hold | The wallet has no hold, so the charge could overdraw it. The rule depends only on the firing, so play and replay agree. | Yes |
| A charge inside a firing under a seal that the meter does not gate (the client's own wallet) goes to the client's phlo limit at once, as before | Keep it in the buffer | The client's limit already bounds it. See known issue 3. | Yes |
| A bound is held until the end of its run (Decision 126) | — | — | — |
| A hold that fails in replay fails the replay ("a replayed COMM is not covered by the share of its wallets") | — | Replay checks each logged COMM. Holds only increase, so the order of the COMMs does not change the result. | — |
| `membrane::unbounded_charges()` counts a gated charge outside every firing and outside the COMM settlement | No counter | A diagnostic for a code path that the design does not expect | Yes |

## 4. Known issues (Decision 88: not blocking)

1. **Small wallets in full blocks (Decision 125).** A run may hold free(W) / n. In a block with many envelopes, a contract with a small wallet is not fired. The datum and the receive both stay stored, as with Decision 79's filter. A later operation on the channel can match them.
2. **A seal bound at run time inside stored code.** A body that seals work with a name that it receives cannot name that wallet at match time. A charge to that wallet exhausts the firing (section 2). The run-time check of Decision 112 is unchanged.
3. **Ungated charges in a discarded firing.** Work under the client's own seal inside a firing is charged to the client when it is done. If the firing is then discarded, the client has paid for work that left no effect. This needs a body that seals with the client's key.
4. **Bounds are held until the run ends.** A loop of N firings under one installer in one run holds N bounds. A long loop stops at free(W) / (n × bound) firings in one block and continues in a later block.
5. **Finding for Meredith: the bound is the installing deployment's whole phlo limit.** The installing deployment's `phloLimit` must cover its own run. The same number is then held for each later firing, and each reduction is a firing (Decision 124). Two tests had to change:
   - `forms_spec::work_that_stored_code_pays_for_does_not_count_against_the_clients_limit`: the stored code makes 13 nested reductions. With an install limit of 100,000, one hold already passes the installer's 100,000, so the code did not fire. The test now installs with a limit of 5,000.
   - `gated_executor_spec::a_user_transfer_and_bond_survive_play_and_replay`: the deployment's run needs more than 30,000 phlo, and its handle continuation fires in the close of the same block. The close holds the bound against the balance less the gate's commitment of the same limit. The test now uses 45,000 instead of 50,000.
   - A separate bound declared for each firing would remove this coupling, for example a field in the seal that defaults to the deployment's limit. That is a design change, so it is not built.

## 5. Tests

- `membrane::tests` (rholang): holds and their order, a gated datum's cell, a named wallet that cannot hold, a firing within and past its bound, a charge to a wallet that is not held, exhaustion independent of the order of the charges, scope inheritance, a single precharge.

- `close_charge_spec::no_deployment_makes_the_close_fail`: the close completes, and the installer pays for the work that the close fired.
