# Decisions — P0-04 (A1c part 1: atomic commit_lfb)

Each entry gives the decision, the alternatives, the reason and whether it is reversible.

## D-P0-04-1 — Pin the single-transaction write with a test

- **Decision:** Add `shares_one_lmdb_env` to `shared/src/rust/store/lmdb_key_value_store.rs`. `batched_put` now uses this predicate. `BlockDagKeyValueStorage::commit_lfb_is_transactional` applies it to the metadata, marker and pointer stores. A casper test opens the node store mapping and asserts it.
- **Alternatives:** Trust the mapping without a test. Make `commit_lfb` refuse a non-transactional batch.
- **Reason:** `batched_put` falls back to separate puts when the stores do not share one environment. "A commit is never partial" holds only because of the mapping in `rnode_key_value_store_manager.rs`. The test fails if a later change moves one of the three stores to another environment.
- **Reversible:** yes. The change adds a function and keeps every existing signature.

## D-P0-04-2 — Adapt dev's `failed_finalization_after_lfb_advance_rejects_an_unbonded_deploy`

- **Decision:** The injected effect fails on its first call, and the test expects one call. The rest of the test is unchanged.
- **Alternatives:** Keep dev's reconcile loop beside `commit_lfb`. Drop the test.
- **Reason:** dev's loop ran the effect again when an unfinalized ancestor appeared during the effect. The test used that loop to persist an advance and then fail. `commit_lfb` computes the ancestors and writes under the global write lock. `insert` takes the same lock, so the gap that the loop closed does not exist. The advance persists before the effect, so a failed first effect gives the precondition that the test needs.
- **Effect on behavior:** An ancestor that arrives after the commit becomes finalized at the next commit. The casper buffer inserts parents before children, so in normal operation this applies only to blocks below the restore horizon, which are never held. The LFB decision (`floor_of_view`) does not change.
- **Reversible:** yes.

## D-P0-04-3 — Republishing of unpublished commits waits for P0-07

- **Decision:** P0-04 writes a commit marker per commit and deletes it after the effect succeeds. Nothing republishes a marker that remains after a failed effect until P0-07 lands.
- **Alternatives:** Republish pending markers at the start of each adoption in P0-04.
- **Reason:** Republishing with a commit epoch is the scope of P0-07 (`a6f9155bb`). Phase 0 goes to dev as one pull request, so no release contains the gap.
- **Interim effect:** When a finalization effect fails, its `BlockFinalised` events are not sent again before P0-07. On dev, the next advance retried them.
- **Reversible:** yes.

## D-P0-04-4 — The API path needs no change

- **Decision:** No API change.
- **Reason:** Since dev `ec3e3ef4b`, `last_finalized_block` returns the persisted LFB and never commits. The finalizer is the only writer, and it commits through `record_directly_finalized`, which calls `commit_lfb`.
- **Reversible:** yes.

## D-P0-04-5 — The finalizer passes an accepting validator until P0-07

- **Decision:** `record_directly_finalized` calls `commit_lfb` with a validator that accepts every candidate. `validate_commit` (NotHigher, A-LIN) arrives with P0-07.
- **Reason:** dev's adoption already requires that the candidate captures the current LFB. `commit_lfb` refuses a block that is not in the DAG. The LFB pointer never moves down.
- **Reversible:** yes.

## D-P0-04-6 — Approved inserts write no LFB pointer

- **Decision:** The approved insert (genesis or a restore anchor) keeps dev's direct `record_finalized` and writes no pointer.
- **Reason:** No code reads the pointer in P0-04. P0-07 must read an absent pointer as "use the LFB from block metadata".
- **Reversible:** yes.

## D-P0-04-8 — Toolchain substitute for local checks

- **Decision:** Local builds use stable 1.97 with `RUSTC_BOOTSTRAP=1`, and `protoc` from `grpcio-tools`. Nothing in the repository changes.
- **Reason:** The session proxy denies `static.rust-lang.org`, so the pinned nightly-2026-02-09 cannot install.
- **Limit:** Stable rustfmt ignores the nightly-only options in `rustfmt.toml`, so the format check covers only line width and the stable options. CI must confirm format and clippy with the pinned toolchain.
- **Reversible:** yes.
