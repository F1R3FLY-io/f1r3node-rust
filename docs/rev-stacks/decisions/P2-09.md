# P2-09 decisions: full conservation audit, parametric in token kind

Patch P2-09, rev-stacks patch plan r7.13, lane A2. Branch `patch/P2-09`, cut
from `patch/P2-integration` (`3b5a7e90a`) and then rebased on lane C's
`patch/P3-07b` (`9bf528ed5`) after that branch was pushed. All code in this
patch is new. Nothing is ported.

## Instruction (2026-10-31)

Write conservation parametric in kind now, with REV as the only instance
until lane C's P3-07b lands. Per kind, the sum of balances must equal the
recorded mints. For REV, that sum is the genesis supply: wallets plus bonds
(Decision 32). Keep the kind parameter in an own type until P3-07b defines
the kind identifier, so that the merge with lane C is a substitution and not
a redesign.

## Files touched

- casper: new `v6/conservation.rs`. `v6/executor.rs` (shared with lane B) gets an optional audit hook. `v6/engine.rs` builds the audit. `casper.rs`, `casper_conf.rs` and `casper_launch.rs` carry the interval key.
- node: `defaults.conf` gets `v6-conservation-audit-interval = 64`. Test literals in `diagnostics/tests.rs`, `config_mapper.rs` and `configuration/mod.rs` are updated.
- tests: new `casper/tests/v6/conservation_spec.rs`.

## Tests

- `casper/src/rust/v6/conservation.rs` unit tests: the schedule, genesis mint parsing, a kind is judged against its observed mints, and kinds stay apart in the index.
- `casper/tests/v6/conservation_spec.rs::the_genesis_index_accounts_for_the_whole_supply`: at the genesis root, the indexed REV wallets plus the bonds equal the genesis supply.
- `an_index_that_misses_a_funded_wallet_fails_the_audit`: an index without one funded wallet gives `conserved() == Some(false)`.
- `play_and_replay_audit_on_schedule_and_index_the_new_wallets`: a `rho:rev:wallet` transfer to a new wallet. The play audit and the replay audit are conserved, `failures() == 0`, and the recipient and the proposer are in the index.
- `an_off_schedule_block_is_not_audited`.
- `a_minted_kind_is_audited_against_its_mints`: block 1 mints 3 of a fresh kind, block 2 moves 2 of the kind to a slot. The audit after block 2 gives the kind `minted == held == 3` over two wallets, REV is conserved, and `failures() == 0`.
- `casper --lib v6::`: 96 passed. `node --lib configuration`: 152 passed.

### Tests (P2-09b)

- `replaying_a_minting_block_counts_its_mints_once`: a block mints 3 units of a kind, and the same block is then replayed. The audit reports `minted == 3` and the kind is conserved. With the running total it reported 6.
- `the_wallet_index_survives_a_restart`: after a transfer to a new wallet, a second `Conservation::open` on the same store has the same index, recipient included. An empty store has only the genesis seed.
- `multi_node::v6_engine_state::every_validator_audits_conservation_on_its_schedule`: three validators, interval 2, a transfer to a new wallet. Every validator audits at block 6 or later. Every kind balances, there are no failures, and the recipient is indexed. A conservation reopened from a validator's executor-state store still has the recipient.
- `audit_time_by_index_size` (ignored, measurement, release, 2 cores): 104 wallets 25 ms, 1,004 wallets 28 ms, 10,004 wallets 54 ms. The cost is about 23 ms for a runtime at the root, plus about 3 µs per empty wallet. At the default interval of 64 and 10,000 wallets, the audit adds under 0.1 % to block execution (P1-14: 205 ms for a one-envelope block).
