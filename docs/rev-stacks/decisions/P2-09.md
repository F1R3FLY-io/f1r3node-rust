# P2-09 decisions: full conservation audit, parametric in token kind

Patch P2-09, rev-stacks patch plan r7.13, lane A2. Branch `patch/P2-09`, cut
from `patch/P2-integration` (`3b5a7e90a`) and then rebased on lane C's
`patch/P3-07b` (`9bf528ed5`) after that branch was pushed. All code in this
patch is new. Nothing is ported.

## Instruction (2026-10-31)

Write conservation parametric in kind now, with REV as the only instance
until lane C's P3-07b lands. Per kind, the sum of balances must equal the
recorded mints. For REV, that sum is the genesis supply: wallets plus bonds
(Decision 32). Keep the kind parameter in an own type until P3-07b defines
the kind identifier, so that the merge with lane C is a substitution and not
a redesign.

## Files touched

- casper: new `v6/conservation.rs`. `v6/executor.rs` (shared with lane B) gets an optional audit hook. `v6/engine.rs` builds the audit. `casper.rs`, `casper_conf.rs` and `casper_launch.rs` carry the interval key.
- node: `defaults.conf` gets `v6-conservation-audit-interval = 64`. Test literals in `diagnostics/tests.rs`, `config_mapper.rs` and `configuration/mod.rs` are updated.
- tests: new `casper/tests/v6/conservation_spec.rs`.

## Decisions

| # | Decision | Alternatives | Reason | Reversible |
|---|----------|--------------|--------|------------|
| 1 | The first version used an own type `conservation::TokenKind { Rev, Issued(Vec<u8>) }` as the single substitution point (first push, `9afcb399138fa4cf06561821bf378a150ab99039`). P3-07b was pushed before P1-14 started, so this patch now uses `rev_stack::TokenKind` from P3-07b (decision 1 of `P3-07b.md`) and the own type is gone. A wallet of a kind is at `wallet_channel_id_of(owner, kind)` (P3-07b decision 2). | Keep the own type until the integration merge. | Instruction: take the kind identifier from P3-07b once it is pushed. The substitution was small, as planned. | Yes |
| 2 | Per kind, the audit sums every indexed wallet's balance at the state root, adds the amount held outside stacks, and compares the total with the recorded mints. For REV, the mints are `genesis_supply` and the amount outside stacks is `legacy_bonds` (Decision 32). | Compare against the previous audit. | Instruction. An absolute check finds drift that an incremental check cannot see. | Yes |
| 3 | For a kind other than REV, the recorded mints are the sum of the mint entries (`Source::Mint`) in every settlement that the node observed, in play and replay (P3-07b decisions 5 and 12). The index keeps this sum per kind. `KindAudit::conserved` is `held == minted` for every kind. | A whole-state mint counter in Rholang. | The block records carry every mint, so the sum is complete for a node that observed every block since genesis. The same condition applies to the wallet index (Decision 4). | Yes |
| 4 | No wallet index existed (P2-06 and P2-20 deferred it), so this patch builds a node-local `WalletIndex` per kind. Genesis seeds it: the compute wallet, each address in the genesis `"mint"` deploy, and each bond owner and validator wallet. Each block's bonds and each settlement (play and replay: charge wallets, proposer, and the parties of each transfer and mint in its kind) extend it. | Scan the whole tuple space. Add the index to the state. | Balances are read from state, so an extra wallet in the index is harmless. A missing funded wallet fails the audit, which is the correct alarm. No state change is needed. | Yes |
| 5 | The audit is an alarm, not consensus. A failure is logged with `tracing::error`, counted in `v6.conservation.audit.failures`, and kept in `Conservation::last`. Runs are counted in `v6.conservation.audit.runs`. A read error is logged and does not fail execution or replay. | Refuse the block. | The index is node-local, so two honest nodes can disagree on it. A consensus check must not depend on it. The per-block check in `settle` stays the consensus guard. | Yes |
| 6 | The audit runs on the post-state of each block whose number is a positive multiple of `v6-conservation-audit-interval`, in play and in replay. The default is 64. Zero turns the audit off. | Every block. | Caps and limits are configuration parameters with defaults. The default is a placeholder until P1-14 measures the cost. | Yes |
| 7 | `conservation::check_at(runtime_manager, root, index)` is public. It is the benchmark hook. P1-14's measurement tests call it. | A separate benchmark crate. | Decision 37: P2-09 covers the scheduled audit plus a benchmark hook. | Yes |
| 8 | `settle::audit` (lane B) is not changed. The per-block incremental check stays in P2-06 and P2-21. | Merge the two checks. | Lane boundary. The two checks have different scopes. | Yes |
| 9 | Recorded for reference: for A-6 finding F6, the user chose the seal reading (b). Every draw on a wallet must sit inside a region that the wallet's owner sealed. This patch does not implement F6. The audit reads balances only and draws nothing. | — | Record of a ruling that affects later patches. | — |

## Tests

- `casper/src/rust/v6/conservation.rs` unit tests: the schedule, genesis mint parsing, a kind is judged against its observed mints, and kinds stay apart in the index.
- `casper/tests/v6/conservation_spec.rs::the_genesis_index_accounts_for_the_whole_supply`: at the genesis root, the indexed REV wallets plus the bonds equal the genesis supply.
- `an_index_that_misses_a_funded_wallet_fails_the_audit`: an index without one funded wallet gives `conserved() == Some(false)`.
- `play_and_replay_audit_on_schedule_and_index_the_new_wallets`: a `rho:rev:wallet` transfer to a new wallet. The play audit and the replay audit are conserved, `failures() == 0`, and the recipient and the proposer are in the index.
- `an_off_schedule_block_is_not_audited`.
- `a_minted_kind_is_audited_against_its_mints`: block 1 mints 3 of a fresh kind, block 2 moves 2 of the kind to a slot. The audit after block 2 gives the kind `minted == held == 3` over two wallets, REV is conserved, and `failures() == 0`.
- `casper --lib v6::`: 96 passed. `node --lib configuration`: 152 passed.
