# Decisions — P0-03 (A6: consensus CPU work off the async workers)

Each entry gives the decision, the alternatives, the reason and whether it is reversible.

## D-P0-03-1 — Cherry-pick 568773a3a onto patch/P0-10

- **Decision:** `568773a3a` applied without conflicts. `off_async_workers` (new file `casper/src/rust/util/offload.rs`) wraps three calls:
  - `compute_parents_post_state` (the parent merge) in `create_with_progress`
  - `compute_deploys_checkpoint` (the proposal's deploy execution) in `create_with_progress`
  - `validate_block_checkpoint` (the replay of a peer block) in the validation dispatcher.
- **Alternatives:** `spawn_blocking`. The three futures borrow the caller's stack (`casper_snapshot`, `block_store`, the runtime manager), so they are not `'static`, and `spawn_blocking` needs `'static`.
- **Reason:** dev has no offload on these paths. Its only `spawn_blocking` calls are in LFS sync, the WAL payload applier and the finalizer settle step.
- **Reversible:** yes.

## D-P0-03-2 — Current-thread runtimes run the work inline

- **Decision:** Keep Track A's rule. `block_in_place` panics on a current-thread runtime, so `off_async_workers` awaits the future directly there. Most unit tests use a current-thread runtime and so keep their old behavior.
- **Reversible:** yes.

## D-P0-03-3 — Callers checked for cancellation and sibling futures

- **Decision:** No change needed.
- **Reason:** `block_in_place` blocks the whole task. A `select!`, `join!` or `timeout` around the offloaded call would wait until the call ends. No caller of the three wrapped calls has one. The `join!` in `proposer.rs` covers only the stake and height checks. The `timeout` in `block_api.rs` covers exploratory deploys, which do not use the offload.
- **Reversible:** yes.

## D-P0-03-4 — Format and commit subject

- **Decision:** The cherry-picked commit takes the `[agent]` subject prefix and keeps the `-x` line. A second commit applies stable rustfmt to the ported test lines. No ported comment is changed.
- **Reversible:** yes.
