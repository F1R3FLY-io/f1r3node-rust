`patch/P2-12`, cut from `patch/P2-03`. All code in this patch is new. Nothing
is ported.

## Done-when, as narrowed

Ruling of 2026-10-30: P2-12 is done against a narrowed done-when. The signed
transfer deploy that `node transfer` builds runs on a casper `TestNode`
runtime at the genesis post-state, with wallets seeded directly. The test is
`util::rholang::cli_transfer_test` in `casper/tests`, and it passes.

The run of the `node` binary against a running v6 shard moves to P2-13
(ruling of 2026-10-30). It needs P1-03 and P2-02 on the base.

## Open items

1. **Wiring of the wallet path.** When `CasperShardConf.v6_order_then_execute`
   is on the base, set `WalletPath::Native` from that flag in `setup.rs`. Do
   this together with the gate for `rho:rev:wallet` in the P2-03 decision log.
2. **Transfer history.** `web/transaction.rs` extracts transfers from the
   SystemVault log channel in block reports. A native transfer writes no event
   log, so the transfer history of the web API does not show native transfers.
   Ruling of 2026-10-30: a new patch, P2-20 in lane B, builds the history from
   the record after P2-06 and P2-12. This lane does not build it.
3. **Embers and the gateway.** The brief says that they follow this patch.
   They are in other repositories, and this patch does not change them.
4. **Address validation on `dev`.** Ruling of 2026-10-30: the validation of the
   address in the legacy balance query also goes to `dev` as its own fix, on
   the branch `fix/web-api-address-validation`. When this branch rebases onto
   a `dev` that contains that fix, keep the check of decision 4 and drop the
   duplicate.
