## Decisions

| # | Decision | Alternatives | Reason | Reversible |
|---|----------|--------------|--------|------------|
| 1 | The reducer COMM hook is `CostManager::record_comm`. The charging space calls it once for each COMM, where the COMM event storage charge is made: a send meets a receive, a join fires, or a peek fires. `CommLedger` counts the COMMs and cuts them into box-car batches. | A counter in `reduce.rs`. | The charging space is the one place that sees every COMM of a metered run. The test shows that the hook count equals the number of COMM events in the event log, for joins, contracts and peeks. | Yes |
| 2 | The settlement uses the COMM count of the run (`EnvelopeRun.comm_phlo`), which P1-04 takes from the user log. The ledger count is the same number (decision 1). The executor round reads the ledger in play and keeps the log count in replay. | Read only the ledger. | Replay runs without cost accounting (P1-04 decision 3), so the hook does not fire in replay. The log count replays by construction. | Yes |
| 3 | COMM charge: `k_comm = min(comm_phlo, delta)`, and the charge is `k_comm × phloPrice`, debited from each paying wallet and credited to the proposer. The proposer is the wallet of the block's sender public key. A refused envelope pays nothing. A charge larger than the envelope's commitment is an error. | — | Design §6.3 and §6.5. P2-15 adds the compute charge, and the cap then covers both charges. | Yes |
| 4 | Canonical form (Decision 9, accepted): settlement runs in block order on the merged state. Each wallet that pays ends with one combined datum. The proposer's channel gets one new deposit datum for the block. Intermediate debits are never in the state. A block that charges nothing leaves the state root unchanged. | — | Decision 9. | — |
| 5 | Box-car: `settle::Boxcar(Option<NonZeroU64>)`, the number of COMMs per debit write. The default is unbounded (one write per envelope). The same value sets `CommLedger::set_boxcar`, which cuts the run's COMMs into batches. The settled root is the same for every box-car size, and the test checks sizes unbounded, 1, 3 and 64. | — | Decision 6: box-car is a per-node configuration parameter. It changes only the write schedule, never the state. The default is not measured, because the size has no effect on the state. The executor round adds the node configuration key. | Yes |
| 6 | `settle::settle_block(runtime_manager, mid_root, inputs, entries, runs, proposer, boxcar)` is the call surface for the executor. It resets a runtime to the merged root, applies the settlement natively and checkpoints. Settlement code runs no Rholang and leaves no event log. | Settle inside `executor.rs`. | It keeps the executor's change to one call (ruling: keep changes to the executor's call surface). | Yes |
| 7 | Reservations: before a run, the executor writes a native reservation for each paying wallet. `visible` is the commitments through the envelope's gate position (Decision 9). `held` is the block's total commitment on the wallet. `balance` returns the balance less `visible`. `transfer` refuses a payment that would leave less than `held`. The reservation is cleared before the checkpoint, and the test shows that it leaves no trace in the state root. | See memo M-5. | A run can move REV natively. Without a hold, a run could transfer away REV that a later envelope in the same block has committed, and settlement could not take its charge. | Yes |

## Memo M-5: the spend limit inside a run

Decision 9 fixes what a term sees when it reads its own wallet: the pre-state
balance less the commitments up to its own gate position. It does not say how
much a run may move out of the wallet. If that limit is the visible balance,
an earlier envelope can transfer away REV that a later envelope of the same
wallet has committed. Settlement then cannot take the later envelope's
charge, and conservation or the charge rule breaks.

- (a) Recommended, built: the spend limit inside a run keeps back all of the block's commitments on the wallet (`held`). The read shows `visible`. A term can therefore see slightly more than it can move.
- (b) Make the read equal to the spend limit (all of the block's commitments). This reverses Decision 9 for reads.
- (c) Settlement charges what is left. A short charge breaks Decision 14.

If (a) is wrong, a contract that reads its balance and then tries to move all of it gets a refusal where it expected success.

## Tests

- `accounting::comm_ledger::tests`: counting, batches, reset.
- `rholang/tests/comm_ledger_spec.rs`: the hook count equals the COMM events in the event log, for six terms. Box-car batches partition the COMMs.
- `rholang/tests/rev_reserve_spec.rs`: a run sees its visible balance and cannot spend held REV. A cleared reservation leaves the state root unchanged.
- `casper/tests/v6/settlement_spec.rs`, on a v6 genesis with the real gate: COMM charges move to the proposer, a refused envelope pays nothing, `k_comm` is capped at delta, the total REV stays the same, and settlement is deterministic. The settled root is the same for four box-car sizes. A block with no charge keeps its root.
