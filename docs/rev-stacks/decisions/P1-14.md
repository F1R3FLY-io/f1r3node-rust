## P9 and P10

The changes are test code and test harness only. No change moves, mints or redirects value, or checks an identity. Decisions 2 and 3 make the harness configure a v6 shard as a node does.

## Tests

- `multi_node::v6_order_then_execute` (P1-02, 4 tests).
- `multi_node::v6_lag_gate::a_lagging_validator_proposes_without_envelopes_until_it_catches_up` (0031).
- `multi_node::v6_inclusion_checks::a_block_that_orders_an_unfunded_envelope_yields_inclusion_evidence_on_every_validator` (0032). The gate refuses the envelope, the block's executor does not run it, and every validator reports one inclusion violation against the proposer.
- `multi_node::v6_engine_state::a_restarted_engine_resumes_its_canonical_prefix_without_replaying_it` (0030).
- `multi_node::v6_engine_state::a_long_run_keeps_executor_memory_flat_and_old_receipts_available` (0034, 72 rounds).
- `v6::exit_spec`: cross-host replay from the fixture, replay on a second host, the cost breakdown, record bytes and validation at the byte cap, the fixture writer and the phase timings (the last two are ignored).
