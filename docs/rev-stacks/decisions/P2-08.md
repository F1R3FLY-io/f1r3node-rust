# P2-08 decisions: REV hook and hook authority

Patch P2-08, "REV hook and hook authority", rev-stacks patch plan r7.2,
lane B. Branch `patch/P2-08`, cut from `patch/P2-07`. All code in this patch
is new. Nothing is ported.

Q-19 (fixed or changeable threshold) and Q-20 (when the hook is called) are
open. Memo M-4 covers both. This patch builds only the parts that do not
depend on them:

- the no-op REV hook, installed at genesis
- the genesis addresses and threshold
- hook replacement that needs the threshold of those addresses
- the call point after each block's settlement.

## Decisions

| # | Decision | Alternatives | Reason | Reversible |
|---|----------|--------------|--------|------------|
| 1 | The hook authority and the REV hook are native datums on channels hashed from the domain tags `f1r3fly/rev-stack/hook-authority/v1` and `f1r3fly/rev-stack/rev-hook/v1`. | Rholang contracts in the registry. | The settlement path reads them natively, with no contract code (design §6.5). | Yes, before any shard launches |
| 2 | Genesis installs them through the genesis-only `rho:rev:genesis` process (command `hooks`), in one deploy after the stack batches. A second install is refused. | A separate URN. | Same mechanism and the same replay property as P2-02 (decision 1 of P2-02). | Yes |
| 3 | The genesis addresses and threshold are dev's PoS multi-signature keys (`pos_multi_sig_public_keys`) and quorum (`pos_multi_sig_quorum`), turned into REV addresses. | A new genesis input. | dev already names a multi-signature set at genesis, and a new `Genesis` field changes nine construction sites. This is an authority choice. See memo M-4, item 3. | Yes, before any shard launches |
| 4 | Members are single signatures, deduplicated and sorted by canonical bytes. The threshold must be in `1..=n`. | — | A fixed, canonical form for a value in the genesis state. | Yes |
| 5 | `replace_rev_hook(store, signers, hook)` succeeds only if every signer is a member and at least `threshold` distinct members sign. It replaces the hook with one datum. | Count non-members. | Decision 7: "No other signer can change a hook." A non-member in the compound is refused, so no member can add an outsider's authority. | Yes |
| 6 | No Rholang URN calls `replace_rev_hook` yet. | A multi-approval contract in the style of MultiSigSystemVault. | The design asks for a deployment with a compound signature over the addresses. Phase 2 admits only the deployer's signature. Compound signatures arrive in phase 3 (lane C syntax), and they then call this function. | Yes |
| 7 | The REV hook is `Noop` (an empty `Par`) or `Contract(Par)`. `v6::hooks::after_settlement(store)` gives `HookCall::Noop` or `HookCall::Contract(p)`. Settlement (P2-06) calls it after it settles each block and runs a contract hook before the conservation check. | — | Design §6.8: the hook runs after settlement, and conservation is checked after it. | Yes |
| 8 | `HookPoint::EpochBoundary` exists but nothing calls it, and `rev_hook_call` returns `Noop` for it. | Wire the epoch boundary. | Q-20. | Yes |
| 9 | The threshold is fixed at genesis. No operation changes it. | An authority-signed threshold change. | Q-19. A fixed threshold is the conservative choice until Q-19 is answered. Adding a change operation later does not change the stored form. | Yes |

## Tests

- `rev_stack::hooks::tests`: threshold and member checks, a single genesis install, and replacement. Replacement is refused with too few signers, with a repeated signer, and with an outsider. It succeeds with the threshold and with all members.
- `rholang/tests/rev_genesis_spec.rs`: a user deploy cannot install hooks. Genesis installs the authority and the no-op hook.
- `casper/tests/v6/hooks_spec.rs`: a v6 genesis holds the PoS multi-signature set as the authority, and `after_settlement` gives `Noop`. A legacy genesis has no authority.

## Rulings of 2026-10-30 (Decision 31)

- Q-19: the threshold is a fixed k of n, set at genesis. Decision 9 above stands.
- Q-20: the REV hook runs after every block's settlement, before the conservation check. Decision 8 above stands: nothing calls the epoch-boundary point.
- The hook authority stays with the PoS multi-signature keys and quorum (decision 3 above).
