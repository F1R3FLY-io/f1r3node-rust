from `patch/P2-06` (lane B), which contains P2-15, P2-14, P2-08 and P2-05.

## Tests

- `rholang/tests/storage_left_in_space_spec.rs`:
  - `a_matched_send_and_receive_pay_no_storage`: four terms, joins included. The net storage is 0 and there is no COMM event-storage charge. dev's rule charges each term.
  - `an_unmatched_send_or_receive_pays_its_storage_once`: equal to dev's charge for an unmatched send or receive.
  - `a_persistent_send_or_receive_pays_once_however_often_it_matches`: a persistent send matched three times, and a contract called three times.
  - `a_run_gets_no_refund_for_what_an_earlier_run_left`: a later run that consumes an earlier run's datum pays 0 storage. dev's rule refunds it.
  - `a_peek_at_what_an_earlier_run_left_pays_nothing`.
- `accounting::storage_rule::tests`.
- `casper/tests/v6/executor_spec.rs::envelopes_pay_only_the_storage_they_leave_and_replay_agrees`: the executor charges a matched pair less than dev's `process_deploy`. A block with persistent sends, a peek and a contract replays with the same cost and post-state.

## Memo F (Decision 19)

See the report of 2026-10-30. The options: (1) apply Decision 19 as the brief states (built). (2) Keep dev's cross-envelope refund and charge only the COMM change. (3) Keep dev's meter until rent lands. If (1) is wrong, a run that consumes data left by other runs pays more than on dev. A busy shared channel then costs its consumers more, and its producers carry the whole storage cost.
