# P2-14 decisions: the compute wallet

Patch P2-14, "The compute wallet", rev-stacks patch plan r7.2, lane B.
Branch `patch/P2-14`, cut from `patch/P2-08`. All code in this patch is new.
Nothing is ported. The code is in
`rholang/src/rust/interpreter/accounting/rev_stack/compute.rs`.

| # | Decision | Alternatives | Reason | Reversible |
|---|----------|--------------|--------|------------|
| 1 | The compute wallet is a located REV stack whose owner is `WalletOwner::Unforgeable(blake2b256("f1r3fly/rev-stack/compute-wallet/v1"))`. Its channel comes from P2-01's `wallet_channel`. | The owner keyed by the compound of the authority addresses (a joint wallet, Decision 25). | A joint wallet keyed by all n addresses needs all n to spend. The design asks for the threshold k of n. A fixed, domain-tagged owner keeps the wallet independent of a later change to the authority (Q-19). | Yes, before any shard launches |
| 2 | Genesis "creates" the empty wallet by fixing its owner. An empty stack has no datum, so a v6 genesis writes nothing for it. The test checks that its balance at the genesis post-state is 0. | Write a zero cell. | A zero cell is not a valid amount cell (P2-01). | Yes |
| 3 | `spend_compute` needs `ComputeSpender::Authority(signers)`, where the signers pass the same check as hook replacement (threshold of the genesis addresses, no outsiders), or `ComputeSpender::InstalledHook`. | — | Design §6.8: a deployment with the compound signature, or the work of a hook they installed. | Yes |
| 4 | `InstalledHook` is an in-process capability. Only the settlement code that runs the installed REV hook (P2-06 / `v6::hooks::after_settlement`) gives it. No Rholang URN reaches `spend_compute`. | A Rholang process. | Phase 2 has no compound-signature deployments (see P2-08 decision 6). `rho:rev:wallet transfer` cannot pay from the compute wallet, because only a deployer id can pay (P2-03 decision 4). | Yes |
| 5 | `deposit_compute` is the settlement credit: one deposit per block (§6.3). Settlement combines the block's compute charges before it calls the function. | — | Design §6.3: one deposit per block. | — |
| 6 | The compute wallet cannot pay itself. | — | A self-transfer would only rewrite cells. | Yes |

## Tests

- `rev_stack::hooks::tests::the_compute_wallet_starts_empty_and_spends_only_under_the_authority`: the wallet starts at 0, and deposits add. A spend is refused with one signer, with an outsider, to the wallet itself, and above the balance. A spend succeeds with the threshold and as an installed hook. The REV moves to the payee, and nothing is created or destroyed.
- `casper/tests/v6/hooks_spec.rs`: the compute wallet balance at a v6 genesis post-state is 0.
