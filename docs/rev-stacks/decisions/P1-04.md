# P1-04 decisions: the executor on dev's meter

Patch P1-04, rev-stacks patch plan r6.3, lane A. Branch `patch/P1-04`, cut
from `patch/P1-03` (P1-03 is not yet on the phase branch).

| # | Decision | Alternatives | Reason | Reversible |
|---|----------|--------------|--------|------------|
| 1 | Each envelope runs in its own runtime session, reset to the block pre-state, through dev's `RuntimeOps::process_deploy_with_mergeable_data`: the user term only, on dev's per-runtime meter. Precharge and refund are not run. | dev's `compute_state` with one deploy (runs precharge and refund). | Charging is off until phase 2. With precharge and refund, the deploy log carries the vault contract's events (128 COMMs for a term with 2), so the log no longer counts the term's COMMs. | Yes |
| 2 | Compute phlo is the cost of dev's meter for the run (`ProcessedDeploy.cost`). COMM phlo is the number of COMM events in the run's user log. | A counter inside the reducer. | The user log already records every COMM the term fires, and replay checks the log, so the count replays by construction. It needs no change to rholang accounting (lane C). | Yes |
| 3 | Replay runs each recorded envelope with dev's `replay_deploy_e` without cost accounting, against the recorded log, from the same pre-state. | Re-run and compare. | The race outcome inside a run is fixed by the recorded log. dev's replay checks the log and the cost. | Yes |
| 4 | Merge in block order: `v6/merge.rs` ported from the integration branch (4cb619605) with one adaptation for dev: `compute_merged_state` takes a `source_of` argument, which is the envelope's id. A later envelope that conflicts with a kept one is not merged. | — | Two envelopes adding the same datum are then flagged as order-dependent, as for two blocks. | Yes |
| 5 | A failed envelope is not merged. dev's `process_deploy` already reverts a failed term to its soft checkpoint. | Merge its (empty) effect. | Same mid-root, simpler. What a failed or conflicted envelope pays is phase 2 (Oct 25: a conflicted envelope still pays for its run). | Yes |
| 6 | The number of concurrent runs is a constructor argument with no default constant. | A hard-coded default. | Caps and limits are configuration parameters. The node configuration supplies it when the executor is wired. | Yes |
| 7 | `rho_settlement.rs` and `settlement.rs` are not ported. There is no settlement contract and no system log. | — | Brief. | — |
| 8 | The executor is not yet wired into `V6Engine` and the records. The engine still uses the tranche-1 `ConcurrentBackend`. | Wire it now and change the record format. | The record format with per-envelope counts and logs is P1-06 (0029), and the switch of v6 shards to the executor touches `casper.rs` and block admission (hook points, P1-01 round 2). | Yes |
