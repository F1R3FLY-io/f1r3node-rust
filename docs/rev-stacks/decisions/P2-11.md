# P2-11 decisions: removal of the vault-based path (v6 shards)

Patch P2-11, rev-stacks patch plan r7.2, lane B. Branch `patch/P2-11`, cut
from `patch/P2-20`. All code in this patch is new. Nothing is ported.

## Rulings that set the scope (2026-10-30)

- dev's legacy (non-v6) mode stays. Every change is on v6 shards only. The legacy genesis, `SystemVault.rho`, `MultiSigSystemVault.rho`, `PoS.rhox`, and the precharge and refund system deploys are unchanged, and their tests still pass.
- Bonds move to a native bond channel per validator, under a domain-tagged owner. Bond and withdraw are native transfers between the validator's wallet and that channel. Slashing moves the bond to the compute wallet.

## What leaves the v6 path

| Removed on v6 | Replaced by |
|---------------|-------------|
| `SystemVault.rho` as the custodian at `rho:vault:system` | `SystemVaultV6.rho` (P2-03's native facade), deployed with the same key, so `rho:vault:system` resolves to it |
| `MultiSigSystemVault.rho` (PoS coop vault for slashed funds) | Not deployed. Slashed bonds go to the compute wallet, which the hook authority holds (P2-14). |
| The empty vault batch that closed `SystemVault.init` (P2-02 decision 9) | Not needed: no legacy `SystemVault` on v6 |
| `PoS.rhox`: `posVault`, the `createWithBalance` bond mint, `deposit`, `chargeDeploy`, `refundDeploy`, `posVaultTransfer`, `getCoopVault`, `getInitialPosVault`, the rewards computed from the PoS vault balance | `PoSV6.rhox`: bond, release and slash through the native `rho:rev:bond`. `getCurrentEpochRewards` gives 0 for each validator, and `committedRewards` stays empty: rewards are the REV hook's (Decisions 2 and 16). |
| The legacy bond total of Decision 32 (P2-05) | The genesis bonds are minted onto native bond stacks. The legacy bond total stays 0, and conservation counts the bond channels as wallets. |

The precharge and refund system deploys (`costacc/pre_charge_deploy.rs`, `refund_deploy.rs`, `check_balance.rs`) never run on the v6 path (P1-04 decision 1). They stay for legacy mode.

## Known limit (memo M-6)

A user's `PoS!("bond", …)` moves REV natively inside the run, and the v6 merge
drops native writes (M-6). Until M-6 is fixed, a bond made by a user deploy
updates PoS's `allBonds` but not the bond channel. Release and slash run in
system deploys, outside the merge, so they persist. Genesis bonds persist.

## Tests

- `rholang/tests/rev_bond_spec.rs`: a deployer bonds its own REV natively. A user deploy cannot slash or release, and a call without a system auth token is refused. With the token, release moves bond REV to the validator's wallet, slash moves the rest to the compute wallet, and a second slash moves 0.
- `rholang/tests/rev_genesis_spec.rs::genesis_mints_the_bonds_onto_native_bond_stacks_once`.
- `casper/tests/v6/pos_v6_spec.rs`: a v6 genesis runs PoSV6 (`getBonds` answers), each validator's bond channel holds its stake, the legacy bond total is 0, and `rho:vault:system` is the native facade.
- `casper/tests/genesis/v6_genesis_wallets_spec.rs` reads v6 balances through the facade. `settlement_spec` audits wallets plus bond channels against the supply.
- All gated and lane A2 executor tests pass with PoSV6's close block. The legacy `genesis_test` and `system_contract_initialization_spec` (14 tests) pass unchanged.
