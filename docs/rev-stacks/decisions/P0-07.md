# Decisions — P0-07 (A1c part 2: resumable floor cursor)

Each entry gives the decision, the alternatives, the reason and whether it is reversible.

## D-P0-07-1 — Build on the P0-06 stack

- **Decision:** `patch/P0-07` starts at `patch/P0-06` (P0-04, P0-02, P0-05 and P0-06). The P0-07 commits are the commits above `docs(rev-stacks): P0-06 decision record`.
- **Reason:** P0-07 depends on P0-06, and the phase branch contains neither.
- **Reversible:** yes.

## D-P0-07-2 — The cursor stays equivalent to dev's floor_of_view

- **Decision:** Keep Track A's cursor phases. Give each cursor one `WitnessMemo`.
- **Reason:** Since the Track A base (`84c2c0b4b`), dev changed `floor.rs` in three ways. `2edcb0bcc` added `WitnessMemo`, which changes the work and not the result. `ec3e3ef4b` removed the unused `in_floor_closure`. A new variant returns the main-parent frontier for validation caching. None of these changes the LFB decision. A cursor holds one snapshot, and `WitnessMemo` is valid for one snapshot. The floor tests compare the cursor with `floor_of_view` at step budgets 1, 3 and unlimited.
- **Reversible:** yes.

## D-P0-07-3 — The finalizer task owns the cursor slot

- **Decision:** `finalizer_cycle` creates the cursor slot next to the oracle cache and `LineageMemo`. The Casper struct, `types.rs` and the six test files keep the dev versions.
- **Reason:** Standing convention: state owned by one task lives with that task.
- **Reversible:** yes.

## D-P0-07-4 — A yield reruns the cycle like a timeout

- **Decision:** When the cursor yields at its budget, the cycle returns as unfinished. The finalizer loop reruns it at once, and the cap `finalizer-timeout-reruns` applies.
- **Alternatives:** Wait for the next trigger after a yield, as Track A did. Track A reran only after the backstop timeout.
- **Reason:** A yield means that the derivation needs more time, which is the case that the rerun exists for. Without a rerun, a node that stops receiving blocks after a burst keeps a half-finished derivation until the next block arrives.
- **Reversible:** yes.

## D-P0-07-5 — Budget, backstop and invalidation limit are configuration keys

- **Decision:** `finalizer-derivation-budget` (default 15 seconds, dev's former `FINALIZER_COMPUTE_TIMEOUT`), `finalizer-step-backstop` (default 60 seconds, from Track A) and `finalizer-cursor-max-invalidations` (default 4, from Track A).
- **Reason:** Standing convention: limits are configuration. These defaults come from dev and Track A, not from a new measurement. A soak can tune them.
- **Reversible:** yes.

## D-P0-07-6 — validate_commit, A-LIN and event republishing as in Track A

- **Decision:** `adopt` commits through `commit_lfb` with `validate_commit`. `ALIN_POLICY` is `Alarm` until P1-10 derives the policy from the protocol version. Events carry the commit epoch. `adopt_derived` publishes every pending marker again before it adopts. This closes the interim gap of D-P0-04-3.
- **Reason:** These are the parts of `a6f9155bb` that dev lacks. `record_directly_finalized` stays in block storage for its tests, but the finalizer no longer calls it.
- **Reversible:** yes.

## D-P0-07-7 — Public module for the integration tests

- **Decision:** `multi_parent_casper::finalization_runner` becomes `pub mod`, and `validate_commit` and `ALinPolicy` become `pub`. This follows `634976db2`.
- **Reason:** `casper/tests/batch2/validate_commit_test.rs` calls them from outside the crate. As a side effect, `ALinPolicy::Halt` no longer gives a dead-code warning, so the `allow` from `c4b8b40c4` is not necessary.
- **Reversible:** yes.
