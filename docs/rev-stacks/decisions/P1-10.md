# P1-10 decisions: 0033 A-LIN policy from the protocol version

Patch P1-10, rev-stacks patch plan r7.7, lane A2. Branch `patch/P1-10`, cut
from `patch/P1-09`. Port of 53f6723d2. P0-07 is on this base (M0).

## How 0033 applied

- Clean: `v6/engine.rs` (the linearizer's hold is an error, logged once per held candidate and counted), `metrics_constants.rs` (`v6.linearizer.alin-holds`), and `finality/floor.rs` (tests).
- `finalization_runner.rs` conflicted throughout, because M0 restructured the finalizer (one finalizer task, `FinalizationContext` with the shard conf). 0033's change was applied by hand: the constant `ALIN_POLICY` (always `Alarm`) is replaced by `ALinPolicy::for_protocol(casper_version)`, and the LFB commit calls `validate_commit` with the policy derived from the context's shard conf.

## Decisions

| # | Decision | Alternatives | Reason | Reversible |
|---|----------|--------------|--------|------------|
| 1 | The policy is derived by `FinalizationContext::alin()` from `shard_conf.casper_version`, not stored as a new field. | A field, as in 0033. | On M0 the context already carries the shard conf. The background finalizer and the API path read the same context, so they agree, which is what 0033's field ensured. | Yes |
| 2 | Protocol 6 is `v6::resource_policy::PROTOCOL_V6` (P1-03). The integration branch's `casper::PROTOCOL_V6_VERSION` does not exist on this base. | Add the constant to `casper.rs`. | One constant for protocol 6. | Yes |
| 3 | Legacy shards keep the alarm, protocol-6 shards halt the LFB commit on an A-LIN violation (the Oct 26 decision: "the A-LIN halt/alarm switch derives from the shard's protocol version"). | — | As delivered. | Yes |
