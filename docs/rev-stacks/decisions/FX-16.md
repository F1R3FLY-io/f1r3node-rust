# FX-16: the close bound (lane B)

Decisions 94, 96, 97, 98. Plan r8.16. Scope now: measure the worst-case work of the close's PoS code and choose the bound. The pre-charge applies at execution, and an uncovered close voids the block. The mechanism waits for Q-33.

## Measurement

Method: a v6 block executed and replayed by `BlockExecutor` on a protocol-6 genesis, with the close's undecorated cells and work charged to the proposer at price 1. The proposer's debit, less its settlement credit, is the close's phlo. Release build. Each row is one block after genesis.

| Validators | Epoch length | Pending bonds in the block | Close phlo |
|---|---|---|---|
| 1 | 1000 (no boundary) | 0 | 60,800 |
| 1 | 1 (boundary) | 0 | 139,737 |
| 10 | 1 | 0 | 247,462 |
| 100 | 1000 | 0 | 182,040 |
| 100 | 1 | 0 | 4,400,917 |
| 100 | 1 | 1 | 4,874,406 |
| 100 | 1 | 16 offered, 1 merged | 4,874,460 |
| 100 | 1 | 64 offered, 1 merged | 4,874,439 |

- 100 validators is the full active set of the test genesis (`number_of_active_validators` = 100).
- The epoch boundary dominates: `pickActiveValidators` sorts all bonds, so the close is about 25 times dearer at a boundary with 100 bonds.
- Pending bonds: the bond registrations of a block all write the PoS state cell, so only one of them merges. Each block's close settles at most one new bond.
- Slashing: a v6 block carries no slash system deploy (`require_no_slashes`), so the v6 close runs no slashing code. There is nothing to measure.
- Not measured: an epoch boundary that releases many quarantined withdrawers at once. Each release calls `RevBondAdmin!("release", …)`. This needs a multi-block test with withdrawals and is the next measurement.

## Bound

**`CLOSE_PHLO_BOUND` = 10,000,000 phlo**, about 2.05 times the worst measured close (4,874,544).

- The pre-charge is the bound times the price. The price is 1 until Q-33 says where the proposer's price comes from. A price must be recorded or fixed in consensus, so that replay gives the same charge.
- The test `close_bound_spec::the_close_stays_inside_its_bound` runs each row above and fails if a close passes the bound. It lands with the mechanism, because it measures through the close charge.

## Findings (Decision 88 labels)

1. **The close's work at a boundary grows with the number of bonds, not only the active set.** `pickActiveValidators` runs over `allBonds`. Anyone can bond with `minimum_bond`, so the bonded set, and so the close's work, has no fixed limit. A fixed bound holds only while the bonded set stays near the measured size. **Known issue, not blocking:** the charge never passes the pre-charge, nobody loses funds, and each extra bond locks `minimum_bond`. The fix needs a ruling: a cap on the bonded set, or a bound that scales with it (for example, a fixed part plus a part for each bond).
2. **Substitution into a fired continuation is charged to the firer.** With the same bond, a larger continuation body for the handle raised the proposer's close charge by 291 phlo (180,160 to 180,451). The installer's own charge also rose. The likely cause is the cost of substituting the received data into the continuation body, which runs before the body enters the installer's membrane. **Known issue, not blocking:** the amount is bounded by the size of a body that the installer paid to store. For lane C to confirm, because Decision 94 gives a fired continuation's cells and work to its installer.
