# P1-01 decisions: v6 module (round 1, module only)

Patch P1-01, "v6 module and hook points", rev-stacks patch plan r6.3, lane A.
This round lands the module only; the hook points in `casper.rs` and
`finalization_runner.rs` follow after P0-07, as a later round of this patch.

| # | Decision | Alternatives | Reason | Reversible |
|---|----------|--------------|--------|------------|
| 1 | Port cfc62b6ee unchanged, as its own commit. | Squash the port with the adaptation. | Keeps the port reviewable against its source. It compiled on dev 252a86d1d without changes, so no adaptation commit was needed. | Yes |
| 2 | Keep `CloseBlockDeploy` in `v6/backend.rs`. | Replace it with a v6-local close-block deploy. | It is dev's own close-block system deploy (`util/rholang/costacc/close_block_deploy.rs` on dev), not a cost-accounting import. | Yes |
| 3 | Register the module with `pub mod v6;` in `casper/src/rust/mod.rs`. | None that compiles. | Registering a module is not a hook point. | Yes |
| 4 | Land the slim resource policy (`v6/resource_policy.rs`, `ShardResourcePolicy`) now, in lane A's files. | Wait for P1-03 / P1-04, which first need it. | These are shared types that this lane uses next (P1-03 and P1-04 are also lane A), and they replace `costacc::genesis_resource_policy::AdoptedResourcePolicy` in the integration branch's v6 files. | Yes |
| 5 | The policy carries only what the v6 seam reads from `AdoptedResourcePolicy` (the per-block record count and record bytes, from `protocol_caps()`) plus the two existing structural limits (`max_envelopes`, `demand_cap`). Funding-search and authority-search caps are left out. | Carry the full `ProtocolCaps`. | The search caps belong to costacc's funding and authority search, which the r6 design removes (§6.12). | Yes |
| 6 | All four values are configuration fields with defaults (64 records, 8 MiB, 256 envelopes, 5e10 demand cap), deserialisable from kebab-case keys, with missing keys taking their defaults; `Limits::default()` now derives from `ShardResourcePolicy::default()`, so each default is set in one place. | Leave the constants in `Limits::default()`. | Caps are configuration parameters, never hard-coded; the 64 / 8 MiB defaults are the Oct 26 B4 decision. Where the policy is loaded from (genesis or node configuration) is P1-03's to wire. | Yes |
| 7 | Run types (`v6/run.rs`): `EnvelopeRun` carries COMM phlo and compute phlo separately, plus failed, user log and post-root; `RecordedRun` is the recorded view that replay compares against. | Port `OfferedRun` / `RecordedRun` from `direct_wallet_funding` (grant issuances, owner binding, budget recording, operation journal). | r6 §6.5 and P1-04 record COMM and compute phlo per envelope from dev's meter and a COMM counter. The costacc fields belong to the funding path that phase 1 drops. Per-wallet kappa is phase 2 (P2-06). | Yes |
| 8 | No `owner_offer` replacement in this round. | A test helper that builds a plain signed `DeployData` envelope. | Its only uses are tests in the integration branch's `propose.rs` and `validity.rs`, which arrive with P1-03 together with the plain signed `DeployData` envelopes it defines. | Yes |

## Build environment note

The pinned toolchain (`nightly-2026-02-09`) could not be installed in the
session (static.rust-lang.org is blocked by egress policy). Builds, tests and
clippy ran on stable 1.97.0 with `RUSTC_BOOTSTRAP=1`. Stable rustfmt ignores
the repository's nightly-only options; the only differences it reports in
these files are single-line function bodies, which `fn_single_line = true`
produces on nightly.
