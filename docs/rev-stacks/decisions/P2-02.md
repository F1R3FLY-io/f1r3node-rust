## Outside the hotspot list (memo item M-1)

The patch changes three rholang files that lane C owns. Each change is small.

- `reduce.rs`: one more check in `eval_new`, under the existing filter flag.
- `rho_runtime.rs`: one `Definition` for `rho:rev:genesis`.
- `system_processes.rs`: fixed channel 70, body ref 70 and the `rev_genesis` handler.

The new file `accounting/rev_stack/genesis.rs` holds the logic. Adding a file is not a hook point.

## Known gaps, for later patches

- PoS still mints the bond sum through `createWithBalance` at genesis, in a legacy vault. That REV is outside the native genesis supply. P2-10 (conservation) must count it, or P2-11 must move bonds to validator channels first.
- `genesis.supply` (dev's vault mint supply parameter) is not used on a v6 genesis. The recorded supply is the sum of wallets.txt.

## Tests

- `rholang/tests/rev_genesis_spec.rs`: a user deploy cannot bind `rho:rev:genesis`. With the filter off, `mint` makes one cell for each wallet, sums duplicates and records the supply. A second batch adds to the supply. A bad line mints nothing.
- `casper/tests/genesis/v6_genesis_wallets_spec.rs`: a v6 genesis with 234 lines in three batches (duplicates and a zero line included). The recorded supply equals the sum of wallets.txt, each stack holds its line, and the legacy vaults hold nothing. The genesis block replays to the same post-state. A legacy genesis mints no native stacks and keeps its vault balances. A supply larger than `MAX_AMOUNT` is refused.
