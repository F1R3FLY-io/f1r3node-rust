plan r6.4, lane C. Branch `patch/P2-03`, cut from `patch/P2-01`. Commit

## Required before phase 2 merges

Ruling of 2026-10-30. The runtime must register `rho:rev:wallet` only on v6
shards. Gate the registration on `CasperShardConf.v6_order_then_execute`,
which `patch/P1-01-hooks` adds. Gating only the facade is not sufficient.

Reason: on a shard that is not v6, the multi-parent merge of `dev` builds
state from event logs. That merge does not see native writes, so a native
transfer on such a shard can be lost or applied twice.

Status: open. The flag is not on the base of this branch yet. When the flag
is on the base:

1. Remove the `rho:rev:wallet` definition from `std_system_processes`.
2. Make a function in the rev-stack module that returns the definition.
3. In casper, pass that definition through `extra_system_processes` only when
   `v6_order_then_execute` is true, in play and in replay.
4. Add a test that a shard that is not v6 cannot resolve `rho:rev:wallet`.
