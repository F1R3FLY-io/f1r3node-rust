# P1-09 decisions: 0032 deferred inclusion checks

Patch P1-09, rev-stacks patch plan r7.7, lane A2. Branch `patch/P1-09`, cut
from `patch/P1-08`. Port of e6405030a.

## How 0032 applied

- `v6/core.rs`: clean. The core schedules one inclusion check per attested block with envelopes, once its own root for the attested block matches the attestation.
- `v6/engine.rs`: 0032's `check_inclusion` and the call on the executor loop, with the funding gate replaced by an `InclusionScreen` (below).
- `casper/tests/multi_node/v6_inclusion_checks.rs` (three-validator shard, a re-signed block that orders an unfunded envelope) needs the v6 test-network harness and the funding gate. It moves to P1-14, after lane B's gate is wired (P2-05).

## Decisions

| # | Decision | Alternatives | Reason | Reversible |
|---|----------|--------------|--------|------------|
| 1 | The inclusion check calls a new `v6::inclusion::InclusionScreen` (`refused(root, timestamp, envelopes) -> Vec<(envelope id, cause)>`), held in `V6Parts::inclusion`. The default is `AdmitAll`: no envelope is refused, so no inclusion evidence is reported until the gate is plugged in. | Wait for the gate. Call lane B's `gate_block` directly. | The funding gate is lane B's (P2-04, `patch/P2-05`) and is not on this branch. A narrow seam lets lane B plug the gate in without editing the engine's check. The scheduling, the evidence format and the once-per-block rule are as delivered. | Yes |
| 2 | The evidence names the envelope by its deploy signature. | 0032's `identity_bytes` of the offered-funded envelope. | Plain `DeployData` envelopes are identified by their signature everywhere on this branch (P1-04b). | Yes |

## For lane B

To enable the checks, implement `InclusionScreen` over the P2-04 gate at the
attested root and the block's timestamp. Return each refused envelope's
signature and the gate's cause. Set it in `V6Parts::inclusion` in `V6Engine::new`.
