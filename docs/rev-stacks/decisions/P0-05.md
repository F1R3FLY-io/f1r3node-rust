# Decisions — P0-05 (A1a reduced: oracle facts across cycles, rerun after a timeout)

Each entry gives the decision, the alternatives, the reason and whether it is reversible. D-P0-00-1 and D-P0-00-2 set the placement and the configuration of the cache.

## D-P0-05-1 — The finalizer task owns the oracle cache

- **Decision:** `finalizer_cycle` creates the shared oracle cache once, next to `LineageMemo`, and passes it to `compute_last_finalized_block` in each cycle. The cache reaches the clique oracle through `OracleCacheMeter`, a `WorkMeter` with the new `oracle_cache()` hook.
- **Alternatives:** A field on `MultiParentCasperImpl`, as in `8ba8b77f1`. An explicit cache argument on every floor function.
- **Reason:** Standing convention: state owned by one task lives with that task. The meter hook keeps the floor functions unchanged. The change in `shared/src/rust/dag/observation_work.rs` is one default method.
- **Reversible:** yes.

## D-P0-05-2 — The justifications cache is keyed by message

- **Decision:** `latest_justifications_cache` maps a message to its justifications, not a validator to them. Its inserts are bounded.
- **Reason:** A message's justifications never change, so the entry is valid in every snapshot. A validator's latest message changes between snapshots, so a validator key is valid in one snapshot only. The test `a_shared_oracle_cache_gives_the_same_frontiers_across_snapshots` fails when the key is the validator. This was checked by a temporary revert.
- **Reversible:** yes.

## D-P0-05-3 — Three cache bounds, with defaults from measured entry sizes

- **Decision:** The configuration keys are `finalizer-oracle-cache-justifications` (default 8192), `finalizer-oracle-cache-self-justifications` (default 131072) and `finalizer-oracle-cache-ancestors` (default 131072). They are in `defaults.conf`, `CasperConf` and `CasperShardConf`.
- **Alternatives:** One bound for all three caches. Track A used 200,000 for all three.
- **Measurement:** A counting allocator measured the heap per entry with owned 32-byte hashes. A justifications entry uses 2,908 B at 16 validators, 7,324 B at 64 and 12,972 B at 128. A self-justification entry uses 186 B, and an ancestor entry uses 188 B. With Track A's bound, the justifications cache can grow to about 1.5 GB at 64 validators.
- **Reason:** The defaults are powers of two. They limit the justifications cache to about 60 MB at 64 validators, and each of the other caches to about 24 MB. A soak measurement of hit rates can tune them later.
- **Reversible:** yes.

## D-P0-05-4 — The rerun cap is a configuration key, and it counts consecutive timeouts

- **Decision:** `finalizer-timeout-reruns` (default 3) sets how many cycles in a row can rerun at once after a timeout. A cycle that finishes resets the count. When the cap is reached, the next cycle waits for a trigger. The value 0 disables the rerun.
- **Alternatives:** Give each new trigger a fresh count, as `drive_finalizer_runs` did in Track A.
- **Reason:** dev replaced Track A's per-trigger loop with one long-lived finalizer task (`3a455a679`). A per-trigger count would allow four cycles per block when every cycle times out. The brief says "at most three in a row". The default comes from the brief, and it is a cap, so the standing convention makes it configurable.
- **Reversible:** yes.

## D-P0-05-5 — A panicking cycle counts as a cycle that finished

- **Decision:** When the cycle subtask panics, the loop does not rerun it at once, and the rerun count resets.
- **Reason:** A rerun resumes cached oracle work after a timeout. A panic is a defect, and an immediate rerun can repeat it.
- **Reversible:** yes.

## D-P0-05-6 — Configuration fields touch two node test literals

- **Decision:** `node/src/rust/diagnostics/tests.rs` and `node/src/rust/configuration/commandline/config_mapper.rs` get the four new `CasperConf` fields. `node/src/rust/configuration/mod.rs` gets a test that the shipped defaults match the serde fallbacks.
- **Reason:** These literals list every `CasperConf` field, so they do not compile without the new fields. Lane B patches that add configuration (P0-09, P0-12) can conflict on these lines. Each such conflict keeps both sets of lines.
- **Reversible:** yes.
