**Rates used below.**
- **Edits with a precise spec:** 250-400 lines per hour of (a). For ASI work, the spec is the Rust source being ported or a one-file change. Small one-file edits cost 0.1-0.3 h, mostly reading.
- **Review and fix:** 0.1 h review for a trivial change, 0.2-0.5 h otherwise. A fix round costs 0.1-1.0 h.
- **Rust client builds:** a client that adds `casper` compiles almost the whole node: comm, rspace++, rholang, models, block-storage, graphz, crypto, shared (node/casper/Cargo.toml). A cold build in the client's own target directory takes about as long as a cold node build, 3-5 min, plus dependency resolution [I].

### 1.7 Gaps in the proposal found while estimating

These need the coordinator's confirmation. They are costed inside the items they block, not added as new work.

- **G1. Build flags and cmake, forced by C-1.**
  - The cause:
    - The target `models` crate pulls in `pathmap` (node/models/Cargo.toml:20).
    - `pathmap` depends on `gxhash` and `libz-ng-sys` (node/Cargo.lock, the pathmap entry).
    - `gxhash` refuses to compile without `-C target-feature=+aes,+sse2`: `compile_error!` at `~/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/gxhash-3.5.0/src/gxhash/platform/x86.rs:2`.
    - `libz-ng-sys` needs cmake.
  - Why the consumers need their own setting:
    - Cargo reads `.cargo/config.toml` only from the directory it runs in and its parents.
    - The faucet server and wallet-cli build in their own workspaces, so they need their own setting.
    - `~/.cargo/config.toml` sets no rustflags.
  - Which files lack cmake:
    - fau `server/Dockerfile`;
    - cli `Dockerfile`;
    - infra `deployer-bot/Dockerfile`;
    - infra `local-launch/bot/Dockerfile`.
    - `chain/validator/connector.Dockerfile` already has cmake.
  - What the proposal says:
    - FA-1 has no source change.
    - The bot and connector Dockerfiles need no change.
  - What the fix costs:
    - a 2-line `.cargo/config.toml` (as `rc/.cargo/config.toml` already has);
    - `cmake` added to the apt list in each Dockerfile;
    - included in the C-1, FA-1, WC-1 and X-6a figures (+0.3 h for the bot Dockerfiles).
- **G2. The wallet's `tests-automation` cannot run.**
  - The specs are not in git: `.gitignore:16` excludes `*.test.*`.
  - `wdio.web.conf.js:7` targets LambdaTest.
  - So §9 flow 5 is done by an agent driving a local browser (Chrome and chromium are installed). This is included in X-6.
- **G3. rust-client's integration topology has no `resource-policy`.**
  - Add it (X-4) to run the suite against the target.
  - Commit it only if the coordinator decides so.
- **G4. U2 = ASI policy reaches beyond rust-client.**
  - The proposal has R-4 for rust-client only.
  - asi-chain-client (C-3), the faucet, wallet-cli, the bot, the SDK and the wallet would also need the policy hex.
- **G5. S-1 must stay easy to vendor.**
  - The wallet compiles to es5 (`tsconfig.json:3`), so the encoder cannot use bigint literals.
  - The wallet lacks `@noble/hashes`, so S-1 should take hashing and signing as injected functions.
  - With both, W-1 stays small whatever U3 says. This adds no time.

## 4. The parallel plan with the least total time

### 4.1 How many agents

**Run 4 agents in both variants.**

More agents do not help, for four reasons:
- **The critical path is one sequential chain:** R-1 → R-2 → R-5 → S-1b → S-2 → S-3 → X-6.

- **Network ports:** every network session uses host ports 404xx (rust-client topology, X-3, local-launch). So sessions run one at a time even in variant B.
- **Coordinator reviews:** Block 0 has about 31 review rounds, roughly 4 h of coordinator time. Extra agents queue reviews.
